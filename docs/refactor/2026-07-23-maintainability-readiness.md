# 简单可维护重构准备（2026-07-23）

## 原则

- 先保持行为不变，再整理结构。
- 每次只改一个模块、一个职责边界。
- 能用函数解决就不用类；能用值类型就不用继承；能用固定数组就不用堆分配。
- 核心规则不依赖 raylib、音频、窗口或文件系统。
- 新增功能必须有明确落点；删除代码必须有引用搜索和测试证据。

## 模块边界

| 模块 | 只负责 | 新内容放这里 |
| --- | --- | --- |
| `core` | 固定步、确定性随机、CRC、固定容量容器 | 无玩法语义的底层工具。 |
| `modifiers` | 属性与效果计算 | 新属性、新 modifier 规则。 |
| `skills` | 主动技能目录与装配 | 新技能定义和技能槽规则。 |
| `items` | 物品、材料、词缀、配方 | 新物品、新材料、新配方。 |
| `passives` | 被动星盘目录与规则 | 新节点、新连接、新奖励。 |
| `combat` | 战斗推进、AI、命中、技能运行 | 新怪物、新攻击、新战斗效果。 |
| `dungeon` | 房间、遭遇、奖励、转场、检查点 | 新房间规则、新遭遇、新奖励流。 |
| `persistence` | 存档编码、迁移、事务与恢复 | 新存档字段和版本迁移。 |
| `platform/raylib` | 输入、渲染、HUD、音频、运行时桥接 | 新 UI、音频和表现效果。 |
| `app` | 程序入口和资源复制 | 启动参数和组装代码。 |

## 依赖方向

```text
app -> platform/raylib -> dungeon/persistence -> combat/items/passives/skills/progression/abyss -> modifiers -> core
```

规则：

- `src/core`、`src/combat`、`src/dungeon`、`src/items`、`src/passives`、`src/persistence` 不能包含 raylib 头。
- `platform/raylib` 可以读取领域状态，但领域模块不能调用 UI、音频或窗口代码。
- 存档代码不能推进战斗；战斗代码不能写文件。

## 资源占用规则

- 热路径继续使用固定容量容器，避免每帧堆分配。
- 小集合优先线性扫描，避免为少量元素建临时动态容器。
- 不引入新框架、全局服务定位器或通用 ECS。
- 保留确定性 RNG 调用顺序，避免相同种子结果漂移。

## 下一步优先顺序

1. `dungeon_session.cpp` / `dungeon_transition.cpp`：拆生命周期、事件桥接、奖励提交和转场事务。
2. `checkpoint_codec.cpp`：拆字段读写、版本迁移和错误校验，不改字节布局。
3. `items`：把目录数据和规则函数分清楚。
4. `combat_world.cpp`：新增战斗内容优先放到 AI、目录或命中 helper，不继续扩大主编排函数。

## 每个重构 PR 的最小流程

1. 用 `rg` 找调用方和禁止依赖。
2. 先确认或补充行为测试。
3. 做一个小切片。
4. 跑对应模块测试和架构 guard。
5. 检查没有改输入、数值、存档版本、RNG 或 CMake 链接方向。
