# 可维护重构约束（2026-07-23）

- 一次只拆一个职责边界，保持输入、数值、存档格式和 RNG 顺序不变。
- 使用值类型和固定容量容器；热路径不新增堆分配。
- 领域模块不依赖平台；允许依赖以 `CMakeLists.txt` 和架构 guard 为准。
- `core` 提供底层工具；领域模块管理各自规则与目录。
- `dungeon` 管理地下城流程；`persistence` 只管理存档。
- `platform/raylib` 与 `app` 只负责平台桥接和程序组装。

`core`、领域模块以及 `persistence` 均不得包含 raylib 头；
`dungeon` 与 `persistence` 不得互相依赖；存档不推进战斗，战斗不写文件。

后续依次拆分地下城生命周期、存档编解码和物品目录；不改玩法或存档布局。

每次重构均执行调用搜索、模块测试、架构 guard 和 diff 检查。
