# Stage 15 低资源音乐、环境声与 UI 混音设计

日期：2026-07-20  
分支：`codex/stage15-audio-mix`  
起点：Stage 14 验收提交 `4930d77`

## 1. 目标

Stage 15 在不改变正式玩法需求基线的前提下补齐持续音频和界面反馈：

- 两条流式背景音乐：探索、战斗；
- 两条流式环境循环：普通地下城、深渊；
- 六个短 UI 音效：移动、确认、取消、覆盖层开、覆盖层关、奖励；
- `Master / SFX / Music / Ambience / UI` 五路音量；
- 设置 V1/V2 到 V3 的原位迁移，记录仍保持 44 字节；
- 缺失资源局部降级、固定容量状态机、发行复制和可重复验收证据。

本阶段只改平台表现层、平台设置层、资源、构建和测试，不改变战斗数值、怪物行为、地下城生成、洞口概率、深渊规则、掉落、星盘、死亡继续或游戏存档格式。

## 2. 推荐方案

采用“小型流式混音器”方案：长音频使用 raylib `Music` 流，短 UI 和 Stage 14 战斗音效使用 `Sound`，由一个平台层 `GameAudio` 统一拥有音频设备、资源和总线增益。

不采用把长音乐整段解码进内存的方案；它不符合低资源目标。也不采用通用音频引擎、脚本化事件图或空间音频；这些会扩大依赖和验收面。

## 3. 资源范围

### 3.1 稳定资源 ID

| ID | 发布文件 | 用途 |
| --- | --- | --- |
| `music_explore` | `music-explore.ogg` | 清房、移动和低压力探索 |
| `music_combat` | `music-combat.ogg` | 房间战斗与深渊战斗 |
| `ambience_room` | `ambience-room.ogg` | 普通房间底噪 |
| `ambience_abyss` | `ambience-abyss.ogg` | 深渊房间底噪 |
| `ui_navigate` | `ui-navigate.wav` | 设置行移动和数值调整 |
| `ui_confirm` | `ui-confirm.wav` | 应用、进入和确认 |
| `ui_cancel` | `ui-cancel.wav` | 取消和拒绝 |
| `ui_open` | `ui-open.wav` | 暂停、背包、星盘打开 |
| `ui_close` | `ui-close.wav` | 覆盖层关闭 |
| `ui_reward` | `ui-reward.wav` | 拾取和奖励确认 |

音乐与环境源只采用 OpenGameArt 页面明确标注 CC0 的原始 OGG；UI 源采用 Kenney 官方 UI Audio CC0 包。`SOURCES.md` 固定原始页面、作者、许可、源文件名、发布文件名和 SHA-256。游戏运行期禁止联网、下载或调用外部转码器。

### 3.2 资源预算

- 四个 OGG 与六个 WAV 总磁盘大小不超过 16 MiB；
- UI WAV 统一为 PCM s16le、44.1 kHz、单声道，单个不超过 0.75 秒；
- 同时活跃最多两条音乐流和两条环境流，仅发生在交叉淡化窗口；稳定态各一条；
- 所有容器在打包前由校验器检查，运行期不做格式转换。

## 4. 音频状态机

`AudioSceneInput` 只包含平台层已经拥有的公开表现状态：是否处于战斗、是否为深渊房、暂停/设置/背包/星盘/死亡覆盖层，以及本帧公开 UI 动作。它不读取或回写模拟私有字段。

- 有存活战斗目标或深渊战斗进行中：目标音乐为 `music_combat`；否则为 `music_explore`。
- 当前房为深渊房：目标环境为 `ambience_abyss`；否则为 `ambience_room`。
- 音乐切换 0.40 秒交叉淡化；环境切换 0.25 秒交叉淡化。
- 暂停和设置打开时音乐、环境降至其总线目标的 55%；死亡覆盖层降至 35%。
- UI cue 只由离散状态边沿触发，不因渲染帧重复播放。
- 固定步模拟不等待音频；音频失败、静音或设备不可用不会改变游戏状态。

状态机使用固定大小数组和枚举，逐帧更新不分配内存。相同目标不会重启流，跨房间但目标相同保持连续播放。

## 5. 统一生命周期与降级

`GameAudio` 成为唯一音频设备所有者，组合 Stage 14 `AudioPack`、Stage 15 `StreamPack` 和 `UiAudioPack`：

1. 初始化设备；
2. 加载 Stage 14 短音效；
3. 打开四条流；
4. 加载六个 UI 短音效；
5. 应用已提交的五路音量；
6. 每帧先更新流缓冲，再应用场景目标与 cue；
7. 逆序停止、卸载并关闭设备。

降级必须局部化：单条流缺失时该槽保持静音，不影响其他流；单个 UI WAV 失败时只为该 ID 生成短程序化回退；Stage 14 的逐资源回退语义保持不变。加载失败不得泄漏已经创建的 `Music`、`Sound` 或设备所有权。

## 6. 五路音量与设置 V3

保留现有字段 `master_sfx_percent` 的二进制位置和兼容读取，但 Stage 15 UI 将它显示为 `Master`。新增：

- `sfx_percent` 默认 100；
- `music_percent` 默认 45；
- `ambience_percent` 默认 35；
- `ui_percent` 默认 80。

四个新值使用 44 字节设置记录中原保留的 34–37 字节；38–39 继续必须为零。V1/V2 解码时保留旧主音量、窗口、VSync、过滤器和键位，并为四个新总线填默认值；下一次成功应用写成 V3。全部音量为 0–100、步进 5。

最终线性增益：

`Master × 对应总线 × 场景 duck`。

设置草稿立即预览五路音量；取消必须恢复进入设置前的已提交值；应用仍走现有原子保存和运行时回滚路径。

## 7. UI 行为

设置页在现有主音量行之后增加 `SFX`、`Music`、`Ambience`、`UI` 四行。现有窗口、VSync、过滤器和十项绑定行为不变。提示文案读取当前草稿值，不硬编码旧布局。

UI 音效触发以用户可感知结果为准：选择移动或音量改变播放 navigate；成功提交/进入播放 confirm；取消或失败播放 cancel；覆盖层打开/关闭播放 open/close；拾取和深渊奖励确认播放 reward。死亡、恢复错误和输入门禁的优先级保持不变。

## 8. 验收

- 资源校验：10 项清单、许可页面、SHA-256、OGG 可解码、UI PCM 规格和 16 MiB 总预算；
- 单元测试：场景选择、无重复重启、淡化、duck、五路增益、单资源降级、生命周期；
- 设置测试：V1/V2 迁移、V3 黄金记录、坏 CRC/保留位、五路范围与步进、双槽原子保存；
- 集成守卫：核心/战斗/地下城/掉落/持久化游戏规则层不依赖 raylib 音频，运行期不下载/转码/启动进程；
- 正式 raylib 证据：4 条真实流、6 个真实 UI WAV、局部损坏回退、状态 trace、资源预算；
- 一次完整 VS x64 Release Fresh 构建与全部 CTest；
- 不带测试参数启动发行 EXE，日志确认设备、10 项 Stage 15 资源和 14 项 Stage 14 资源，公开键位输入后进程持续响应。

主观听感无法由自动测试证明，验收报告必须把响度、音色和循环接缝列为人工试听边界，不得虚报。

## 9. 停止条件

完成后停止在 Stage 15 工作树。不得顺带实现语音、3D 空间音频、混响、动态压缩器、主菜单、手柄、macOS 或任何新玩法内容；不得合并 `main`，等待用户决定。
