# 战斗 HUD 与主动技能栏避让设计

**日期：** 2026-08-14
**状态：** 已批准（用户要求持续采用推荐方案）

## 问题

当前普通 HUD 与主动技能栏独立布局。玩家面板使用 `0.625..1.5` 的 HUD
缩放，主动技能栏在低于 1280×720 时仍保持 `1.0`。结果是：

- 800×450、960×540 的技能栏覆盖玩家生命、护盾和经验区域；
- 800×450、960×540、1280×720、1920×1080 的主通知都与技能栏
  `visual_bounds` 重叠；
- 普通 HUD 先绘制，技能栏后绘制，所以保存失败、恢复要求和交互提示会被盖住。

## 目标

1. 保留技能槽、键位、技能名和冷却文字的现有物理尺寸与字号。
2. 主动技能栏不与玩家面板重叠。
3. 主、次通知不与主动技能栏的完整 `visual_bounds` 重叠。
4. 门提示继续使用与实际绘制相同的主动技能布局。
5. 800×450、960×540、1280×720、1920×1080 均满足合同。

## 非目标

- 不改技能数量、绑定、冷却、玩法、绘制顺序或素材。
- 不缩小中文技能文字，不压缩玩家面板内容。
- 不重构其他世界提示、导航面板或调试面板。
- 不运行窗口、完整 CTest 或 `scripts/Test.ps1`。

## 推荐布局

### 主动技能栏

主动技能栏继续使用现有 `ui_viewport_scale()`，因此 800、960、1280 的
技能布局缩放仍为 `1.0`，1920 为 `1.5`。先按屏幕底部居中生成候选布局；
若候选 `visual_bounds` 与玩家面板相交，则仅沿 X 轴右移到：

```text
player_panel.right + 12 * active_skill_scale
```

支持分辨率的最终技能栏左边界为：

| 分辨率 | 技能缩放 | 最终 x |
|---|---:|---:|
| 800×450 | 1.0 | 284.5 |
| 960×540 | 1.0 | 339.0 |
| 1280×720 | 1.0 | 448.0 |
| 1920×1080 | 1.5 | 672.0 |

所有槽位、键位板、冷却板、名称板和总 `visual_bounds` 必须应用同一个水平
偏移，并继续完全位于 viewport 内。若输入尺寸无效，维持现有 fail-closed 空布局。

### HUD 通知

先生成现有 `HudLayout`，再用主动技能栏最终 `visual_bounds` 作为底部 blocker。
主、次通知作为一个整体上移，保持它们原有尺寸和相互间距。主通知底边不得低于：

```text
active_skill.visual_bounds.y - 12 * hud.scale
```

同时，次通知不得越过 `safe_area.y`。四个支持分辨率都有充足空间，不需要
缩短文案或压缩面板。

## 组件与数据流

1. `make_hud_layout()` 仍负责基础 HUD 几何。
2. `active_skill_hud_layout()` 使用基础 HUD 的玩家面板作为水平 blocker，返回
   最终技能布局；门提示与绘制端继续调用这一唯一入口。
3. `hud_layout_avoiding_bottom_blocker()` 只负责整体移动主、次通知。
4. `make_combat_hud_layout()` 组合以上两步，返回 HUD 与主动技能布局。
5. `CombatRenderer::observe_hud()` 保存组合结果；`draw()` 使用保存的主动技能
   布局，确保通知规划和实际绘制消费同一帧几何。

## 错误与边界

- 非正数 viewport 返回无效组合，不访问屏幕外矩形。
- 空、非有限或零面积 blocker 不移动通知。
- 通知上移量统一应用于主、次通知，禁止改变两者间距。
- 若未来出现空间不足的非支持尺寸，通知最多移动到 safe area 顶部；不通过
  缩小字体或让矩形越界来制造“通过”。

## 验证

在既有 `active_skill_view` TestCase 内加入四分辨率矩阵，锁定：

- 技能缩放与槽位尺寸不变；
- 技能最终 x 为上表值；
- 技能 `visual_bounds` 与玩家面板不重叠；
- 主、次通知均在技能 `visual_bounds` 上方，间距至少 `12 * hud.scale`；
- 所有矩形仍在 viewport/safe area 内；
- 门提示继续消费 `active_skill_hud_layout().visual_bounds`。

只构建 `arpg_platform_tests`，运行 `ARPG_ACTIVE_SKILL_VIEW_ONLY=1` 的既有
11 个用例。不会新增 TestCase，也不会运行窗口或全量测试。
