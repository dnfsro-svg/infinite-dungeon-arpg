# Stage 19 大型房间与怪群规模词条设计

日期：2026-07-21
基线：`main` (`adecf56`)

## 1. 目标

Stage 19 将战斗房间的世界面积扩大为当前的四倍，并加入只影响怪物数量的房间词条。房间可以大于屏幕，镜头跟随玩家移动。每个房间进入战斗时一次性生成全部怪物，不再按波次补充。

本阶段只实现一类房间词条：`怪群规模`。不实现怪物伤害、攻速、生命、掉落或其他房间词条。

## 2. 房间尺寸与镜头

- 战斗逻辑边界由 X `[-12, 12]`、Y `[-5.5, 5.5]` 扩大为 X `[-24, 24]`、Y `[-11, 11]`。
- 新房间宽度为 48、纵深为 22，总面积为现有房间的四倍。
- 16:9 画面继续显示 24×11 的逻辑世界区域，因此同一时刻正好看到四分之一房间面积。
- 非 16:9 画面保持相同纵向可视范围并扩展横向可视范围，不拉伸、不裁掉可操作区域。
- 镜头目标直接使用当前渲染插值后的玩家位置并钳制在房间边缘，不增加额外平滑或追赶时间，不允许显示房间外部。
- 人物及怪物的屏幕尺寸以画面高度为基准，不能因房间扩大或切换全屏而缩小。
- 地面、墙体、四个出口、下一层洞口、玩家移动、怪物 AI、投射物、危险区和生成范围统一使用共享房间边界。

## 3. 怪群规模词条

每个普通房间固定拥有一条怪群规模词条：

| 词条 | 权重 | 怪物数量 |
| --- | ---: | ---: |
| 拥挤 | 50% | 12～16 |
| 密集 | 35% | 17～22 |
| 兽潮 | 15% | 23～30 |

- 先按 50/35/15 权重确定词条，再在对应闭区间内均匀抽取最终怪物数量。
- 词条和数量使用从房间种子派生的独立随机域，不消费门、洞口、深渊、生态、怪物选择或怪物词条的随机流。
- 相同房间种子必须得到相同词条、怪物数量、怪物构成和出生位置；死亡重进和读档不得重骰。
- 深度不直接改变上述数量区间。深度难度继续由既有怪物、怪物词条及其他进度系统承担。

## 4. 深渊房数量

- 深渊房先生成普通房间的怪群规模词条和基础数量，再应用既有 1.5 倍强化原则。
- 深渊最终数量为 `ceil(基础数量 × 1.5)`，范围为 18～45。
- 深渊数量不得超过固定怪物池容量；当前容量 96，因此本阶段上限 45 不需要扩容。
- 深渊怪物词条、奖励和其他既有规则保持不变。

## 5. 遭遇生成

- 房间计划固定为一个生成批次；进入战斗时一次性创建全部怪物。
- 遭遇导演先取得房间词条给出的精确目标数量，再按生态权重、怪物职责和安全限制逐只选择怪物，直至达到目标。
- 每个房间至少包含一个可直接交战的非支援目标。
- 保留远程、支援、地面危险和高优先级怪物的安全数量限制，防止一次性生成形成不可读组合。
- 怪物总威胁值继续计算并用于诊断与 HUD，但不再决定本阶段的怪物总数。
- 生成位置覆盖扩大的房间，并避开玩家出生点半径 4.0、四个门中心半径 3.0 和洞口中心半径 3.0 的安全区域。
- 生成失败或固定容量不足时进入明确故障状态，不截断数量、不覆盖已有怪物，也不重新掷骰。

## 6. 数据与模块边界

- `dungeon` 新增独立的房间词条类型、目录和确定性生成逻辑。
- 房间词条不得复用或混入 `combat` 的怪物词条类型。
- `dungeon` 把最终数量交给遭遇导演；`combat` 只接收完整生成批次并模拟怪物。
- raylib 层只读取快照，负责镜头、场景、词条文字和数量显示，不参与词条或怪物数量决策。
- 房间词条由现有稳定房间数据重建，不修改当前存档格式。

## 7. HUD

- 战斗 HUD 显示当前房间怪群规模词条。
- 同时显示初始怪物总数和当前剩余数量。
- 深渊房仍显示深渊标识，并显示应用 1.5 倍后的实际总数。
- 文字必须使用现有中文字体回退和可读性规则，不新增调试专用英文占位文本。

## 8. 不在本阶段实现

- 怪物伤害、生命、攻速、移速或元素强化类房间词条。
- 掉落数量、掉落稀有度或经验奖励类房间词条。
- 玩家在进门前预览、选择或重骰房间词条。
- 小地图、战争迷雾、房间内分区或多房间同时模拟。
- 超过 45 只怪物的遭遇或怪物池扩容。

## 9. 验证

自动测试必须覆盖：

1. 新边界精确为 X `[-24, 24]`、Y `[-11, 11]`，玩家、怪物、投射物和危险区不能越界。
2. 怪群规模词条权重为 50/35/15，三个数量闭区间分别为 12～16、17～22、23～30。
3. 大样本种子测试覆盖三个词条和各自区间端点，并验证分布没有明显偏离配置权重。
4. 同种子重建得到字节等价的词条、数量、怪物构成和出生位置。
5. 普通房数量始终等于词条结果；深渊数量始终为向上取整的 1.5 倍且不超过 45。
6. 所有怪物在同一生成批次出现，清空前不产生后续波次。
7. 最大 45 只怪物同时运行时不溢出怪物、投射物、危险区或事件容量。
8. 生成位置避开玩家、门和洞口安全区，并覆盖扩大后的有效房间范围。
9. 镜头跟随玩家、在四边正确钳制、全屏分辨率下不缩小人物且不产生明显跟随延迟。
10. 四门转场、下一层洞口、死亡重进、存档重载和房间清理流程保持可用。

构建与验收门：

- 相关单元测试先失败后通过。
- Debug 与 Release 全量 CTest 通过。
- raylib Release 可执行文件启动成功。
- 实际全屏检查镜头移动、房间边缘、12 只与 45 只代表性遭遇、HUD 词条和剩余数量。

## 10. 完成条件

代码、自动测试和全屏可视验收全部通过后，Stage 19 才算完成。不得在本阶段扩展第二类房间词条或修改无关系统。
