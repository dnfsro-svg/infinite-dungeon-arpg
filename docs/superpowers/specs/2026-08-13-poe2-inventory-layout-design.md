# POE2 风格背包界面设计

**日期：** 2026-08-13

**状态：** 已确认，待实施计划

**设计方向：** 采用《流放之路 2》主机版的界面骨架与信息层级，保留本项目现有键盘鼠标操作；不复制其美术资源、字体、图标或像素布局。

## 背景与问题

当前装备页是固定三列：左侧约 27% 为角色属性和六个装备槽，中间约 42% 为背包列表，右侧为常驻详情。材料袋又占据详情列底部，导致：

- 背包真正可用的浏览区域偏小；
- 新存档、筛选无结果、全部装备已穿戴都显示成同一句“过滤：无”，玩家容易误以为装备没有加载；
- 详情列一直占位，即使没有选中物品；
- 普通选中和三合一配方选中在正式素材路径上不够容易区分；
- 材料选择、保存锁定和强化结果会竞争同一状态区域；
- 材料袋与详情裁切区互相挤压，长装备信息可能静默消失。

本轮只重新设计背包壳层及其三个页面，不修改战斗 HUD。此前用户选择的“方案 2”以及“采用流放之路 2 的布局”在这里落实为：左侧角色/装备、右侧大背包、详情按需浮动、底部单一状态栏。

## 目标

- 用一个统一全屏壳层承载“装备”“技能石”“材料”三个页面。
- 装备页左侧展示静态角色剪影与六个穿戴槽，右侧尽可能扩大背包装备网格。
- 物品详情只在选中或悬停时浮动出现，不再永久占用第三列。
- 明确区分真正空背包、筛选无结果、所有装备均已穿戴三种状态。
- 保留现有键盘鼠标操作、请求语义、存档结构、装备和材料规则。
- 800×450、1280×720、1920×1080 均完整入屏；中文正文不得低于 12px。
- 本轮新增的壳层、tooltip、状态和差值展示 builder 为纯计算、固定容量、`noexcept`；稳态重复调用不新增动态分配。既有 `InventoryViewCache::filtered_indices` 在 generation 或容量变化时允许沿用原有分配边界。
- 继续只使用现有 `SharedUiFont`、中文目录和 UI material；字体不可用时 fail-closed。

## 非目标

- 不制作实时 3D 角色预览；角色区域使用静态、低对比度剪影。
- 不复制《流放之路 2》的受保护素材、图标、音效或精确视觉资产。
- 不增加手柄导航、拖放、快捷出售、仓库、搜索或排序规则。
- 不修改掉落率、物品生成、装备数值、三合一、强化、技能石或保存协议。
- 不修改战斗 HUD、暂停菜单、被动树、世界提示或输入绑定。
- 不借本轮重写 `MaterialPack` 或全局排版系统。

## 采用的总体布局

```text
┌─────────────────────────────────────────────────────────────┐
│ 背包标题              [装备] [技能石] [材料]   [当前绑定 / Esc] │
├───────────────────────┬─────────────────────────────────────┤
│                       │ 筛选：全部槽位  全部稀有度           │
│   静态角色剪影         ├─────────────────────────────────────┤
│                       │                                     │
│ [武器] [头盔]         │          大型装备网格                │
│ [手套] [胸甲]         │                                     │
│ [饰品] [靴子]         │       选中/悬停时浮动详情            │
│                       │       （不占永久第三列）              │
├───────────────────────┴─────────────────────────────────────┤
│ 状态 / 当前动作                                  操作提示    │
└─────────────────────────────────────────────────────────────┘
```

这是结构借鉴而不是换皮：继续复用项目现有深色金属切片、古金描边、中文字体和物品图标。视觉上减少“面板内再叠一排黑板”的碎片感，每个区域只保留一个主要不透明底板，状态色仅用于语义强调。

## 响应式几何

新增纯布局 `InventoryShellLayout`。几何使用独立的局部缩放：

```cpp
geometry_scale = clamp(min(width / 1280.0F, height / 720.0F), 0.625F, 1.5F);
```

全局 `ui_viewport_scale` 仍不修改。文字字号使用 `max(12.0F, reference_font_size * geometry_scale)`，因此 800×450 可以缩小槽位和间距，但不会把中文压到 9–10px。

参考尺寸规则：

- 外边距 16、区域间距 16、页签栏高 44、底部状态栏高 52；均乘 `geometry_scale`，但页签、筛选、底栏动作和材料卡片的鼠标命中高度不得低于 32 个物理像素，命中宽度不得低于 40 个物理像素。
- 内容区左栏参考宽 440；右栏取得其余宽度。三个支持分辨率下右栏始终比左栏宽。
- 左栏内的装备槽参考尺寸 78×78；以面板实际宽高再做一次不超过 `geometry_scale` 的 fit，绝不越界。
- 右栏包含筛选行和滚动网格；三个 16:9 支持分辨率均使用三列装备卡片，未来更窄的合法 viewport 才可退化为两列，标准宽高与间距随局部比例缩放。
- `InventoryShellLayout` 明确提供 `status_bounds`、`action_bounds` 和 `hint_bounds`：状态文字优先取得可用宽度，中间动作按钮保持最小命中尺寸，右侧提示在 800×450 空间不足时先隐藏、再对状态文字做 UTF-8 安全省略，三者不得重叠。
- 所有派生矩形必须有限、宽高为正、完全位于 viewport；任何一步无效时整个 layout `valid=false`。

### 静态角色区

角色剪影由现有图元绘制为低对比度头、躯干和四肢轮廓，不引入新的模型或纹理流水线。六个真实装备槽围绕剪影：

- 头盔：上中；
- 胸甲：正中；
- 靴子：下中；
- 武器：左上；
- 手套：左下；
- 饰品：右上。

槽位继续映射现有 `ItemSlot`，不创造第二套装备数据。空槽显示中文部位名；已装备槽显示图标、名称和强化等级。单击已装备槽仍执行现有卸下请求，不改变为拖放。

## 页面结构

`InventoryPage` 从当前两个页面调整为三个明确页面：

1. `equipment`：左侧角色装备，右侧装备网格；
2. `skill_stones`：左侧五个主动技能槽及当前槽的辅助槽，右侧未装备技能石；
3. `materials`：左侧保留角色装备概览，右侧使用完整材料网格和材料说明。

顶部三个页签只归 `InventoryShellLayout::tabs` 所有，不再复用技能石专属的两个页签矩形。`active_skill_loadout_layout` 改为消费壳层的左右内容 bounds，删除自身 page button 坐标；三页 input 和 draw 必须使用同一次计算得到的 shell layout，不能保留第二套页签/内容坐标系。打开背包默认进入装备页；现有正式验证调用 `show_skill_stones_page()` 时仍直接进入技能石页。

材料选择跨页保留，但不自动跳页：选中材料后，底部状态栏显示“已选择：材料名 · 切换到装备页选择目标 · 右键取消”，装备页签同时显示目标提示色。玩家主动切回装备页再单击目标，底层仍发送原有 craft/coupon/reinforcement 请求。这样不制造意外跳转，也保留现有“先材料、后目标”的规则。

材料目标只包括现有装备页右侧网格中的未穿戴装备；左侧已穿戴槽、技能石和材料卡片都不是目标。材料选中期间，材料页右击当前已选中的定向材料卡片仍先循环其定向类别；其它右击才取消材料，不触发配方或技能操作。authority 接受制作请求后保持材料选择，直到玩家取消或该材料数量变为零；请求拒绝时同样保留选择并显示可操作状态；同步发现数量耗尽时沿用现有 `sync_selection` 自动清除。

## 装备网格与空状态

装备网格继续使用 `InventoryViewCache`，仍排除已穿戴物品并保持获得顺序。筛选按钮移入右栏顶部，不改变槽位和稀有度的循环规则。

新增纯展示枚举 `InventoryEmptyState`：

- `none`：存在可显示条目；
- `inventory_empty`：没有任何未穿戴装备，且也没有已穿戴装备；
- `all_equipped`：拥有装备，但所有装备都已穿戴；
- `filter_empty`：存在未穿戴装备，但当前筛选结果为零。

对应的居中两级文案：

- `inventory_empty`：**背包中还没有装备** / `击败怪物并拾取掉落后会显示在这里`；
- `all_equipped`：**所有装备都已穿戴** / `悬停左侧装备查看，单击卸下`；
- `filter_empty`：**当前筛选没有结果** / `切换装备槽或稀有度筛选`。

这只解释数据状态，不赠送物品、不修改新存档内容。

空态出现时清除 hover。若持久选中物品不在当前筛选后的可见集合中，只隐藏 tooltip，不清除 `selected_item_id_`；恢复筛选后仍可恢复该选择。这样不会同时显示“无结果”和一个不可见物品的详情，也不会因浏览筛选丢失玩家选择。

## 选中、悬停与配方语义

正式素材是否绘制成功都必须在其后叠加相同的语义层：

- 鼠标悬停：浅钢色 1px 外框；
- 普通查看选中：青色 2px 外框；
- 三合一选择：品红 3px 外框，并显示固定容量角标 `1/3`、`2/3`、`3/3`；
- 材料目标模式：可用目标显示暗金内框，不可用目标不伪装成可操作状态。

同一物品同时是普通选中和配方成员时，品红外框优先，青色以小型详情指示点保留；不会绘制两套重叠边线。

现有键鼠语义保持：

- 单击背包装备：选中并查看；
- 在双击窗口内再次左击：装备；
- `Ctrl + 左击` 或右击：切换三合一选择；
- 单击已穿戴槽：卸下；
- 鼠标滚轮：只滚动当前右侧网格；
- 当前可重绑的背包键与 `Esc`：按现有绑定关闭；顶栏和提示一律消费 `inventory_binding_label`，不得写死 `I`，并以 `右 Shift` 等最长现有标签验证；
- 材料右击取消、强化确认和技能石的选择/装备/交换/取出行为均保持。

输入处理顺序固定为：强化确认弹窗 > 页签 > tooltip pointer blocker > 未遮挡的材料页定向类别切换 > 其它材料取消 > 材料目标请求 > 当前页 `action_bounds` > 三合一选择 > 双击装备或已穿戴槽操作。指针位于 tooltip 内时，左击关闭 tooltip；右击若有材料选择则取消材料，否则关闭 tooltip；其它输入只阻断下层命中。高优先级路径消费后不得继续落入低优先级动作。材料未选中时，右击装备才恢复为三合一切换。

本轮不新增键盘焦点导航。所谓“主机版骨架”只指空间层级与信息组织，输入仍以当前键盘鼠标为准。

## 浮动物品详情

移除常驻 `detail` 列，新增固定容量 `InventoryTooltipView` 与纯布局 `InventoryTooltipLayout`。

### 详情对象

- 鼠标位于有效装备槽或网格卡片上时，悬停对象临时优先；
- 鼠标移开后恢复到持久 `selected_item_id_`；
- 悬停只改变展示，不修改选择、不触发请求、不写存档；
- 无悬停且无选中时不显示详情。

`InventoryRenderer` 可保存一个 presentation-only 的 `hovered_item_id_`，每帧由当前鼠标坐标更新；它不进入 `DungeonSession` 或持久化数据。

### 放置规则

详情不是第四个面板。参考宽度为 `360 * geometry_scale`，物理宽度钳在 224–630px；高度为实际行数所需高度但不得超过 content viewport。它使用不透明单板按候选顺序放置：

1. 来源在右侧装备网格时，放入左侧角色面板；800×450 下 224px 最小宽度仍能完整成立；
2. 来源在左侧装备槽时，放入右侧网格面板；800×450 下同样保证 224px 最小宽度；
3. 若优先侧空间不足，在来源矩形的对侧尝试；
4. 候选必须与来源卡片/槽位保持至少 `8 * geometry_scale` 的间距；整体钳位若重新造成来源重叠，则该候选无效而不是覆盖来源；
5. 最终候选必须完整位于内容 viewport，且不得覆盖底部状态栏或顶部页签；
6. 在三个支持分辨率中，上述相对面板候选是布局有效性的硬条件；若不能成立，则 shell layout 本身无效，而不是让已选中物品静默失去详情；仅未来非支持尺寸可以 fail-closed。

覆盖静态剪影或其它卡片是有意行为：详情出现时临时遮挡低优先级内容，以换取更大的常驻背包网格。来源矩形、两者之间的安全间隙以及 tooltip 组成一个 `hover_retention_corridor`；指针从来源穿过间隙进入 tooltip 时仍保留同一 hover 对象。tooltip 是顶层 pointer blocker：其矩形内的 hover/click 不得穿透到下层槽位、网格或页签，也不发送玩法请求；离开 retention corridor 后重新解析悬停，避免遮挡下层条目导致 tooltip 跳变。

为避免持久选中 tooltip 长期挡住另一侧控件，左击 tooltip 或任一非交互背景只清除 presentation selection 并关闭 tooltip；若材料已选中，材料页右击当前已选定向材料卡片仍优先切换类别，其它右击优先取消材料，否则右击 tooltip 只关闭 tooltip。关闭后在指针离开当前 tooltip/source retention corridor 前抑制同一 hover 对象重新弹出，防止一帧内闪回。tooltip 不提供玩法按钮或滚动，所有这些状态都不写存档。

### 信息层级

详情顺序固定为：名称与稀有度、物品等级/需求等级/强化、基础属性、词缀、**装备后变化**。比较区继续使用现有九个语义组；一个组内所有差值均为零时整行不绘制，非零分量使用固定容量的彩色片段分别显示（正差值绿色、负差值珊瑚红），零分量不占位置。这样不会把最坏情况扩成数十个独立行，也不会继续显示 `+0/+0/+0`。若没有任何差异，显示一行“装备后无属性变化”。

`InventoryTooltipView` 至少提供 24 行和每行 8 个固定片段的容量，覆盖当前最多六条词缀、基础属性及九个比较组。行高使用 `max(13.0F, 18.0F * geometry_scale)`，因此最坏 24 行加内边距仍能进入 800×450 的 content viewport。同一语义组的非零片段若不能进入 224px 行宽，必须在固定容量内续行并计入 24 行总量；若当前最坏数据证明 24 行不足，实施任务必须在不分配的前提下提高固定容量，而不能截掉非零片段。详情文字使用现有 UTF-8 fit/ellipsis，始终保持完整码点。最大词缀装备在 800×450 仍须完整显示所有非零核心行；只允许省略全零比较和装饰性说明，绝不裁半行、丢失非零属性或越出背板。

## 技能石页面

技能石页使用同一壳层而不是独立全屏坐标系：

- 左侧依次排列五个主动技能槽；当前选中槽下方展示其五个辅助槽；辅助槽只读且不是输入命中区；
- 右侧展示未装备主动技能石；
- 空态居中显示“暂无未装备主动技能石”，而不是在第一个槽左上角写“无”；
- 底部状态栏根据选择显示“选择技能石后点击空槽装备”“选择两个技能槽交换”“选择已装备技能后可取出”；
- `action_bounds` 在技能页绘制“取出”按钮，仅当已选中一个非空主动槽、没有保存 pending 且 authority request 可用时启用；800×450 下它仍满足最小命中尺寸，并与五个主动槽、辅助槽和状态文字不重叠；
- 现有 `ActiveSkillLoadoutCommand` 及 authority accepted 后再推进 presentation selection 的规则不变。

## 材料页面

材料袋不再占装备详情底部。`MaterialBagLayout` 改为消费壳层提供的右侧内容矩形和 scale；`process_click`、`cycle_directed_category`、`draw` 必须接收同一份 layout，不能各自按 width/height 反向调用旧 `inventory_layout()`。强化确认继续独立使用全屏 confirmation layout。材料卡片在完整区域内排列，选中材料、定向类别、数量和强化确认仍使用现有 `MaterialBagRenderer` 状态。

材料说明来自 `ui_text_catalog` 中按 `MaterialId` 映射的中文 presentation 文案，不读取 core catalog 的英文名称。即使所有数量均为零，材料页仍展示完整材料目录和 `×0`，卡片为禁用态而不是显示空页面。

强化确认弹窗继续位于全屏中心，位于所有背包内容之上；标题、问题、确认、取消均保持不透明背板、共享字体与当前请求语义。弹窗开启时底层页签、槽位、网格和 tooltip 都不接受点击。

## 单一底部状态栏

新增纯展示 `InventoryStatusPresentation`，每帧只选择一条状态，避免相互覆盖。优先级固定为：

1. 保存中锁定；
2. 保存失败/恢复要求，以及真实存在的强化或强化券 receipt；
3. 已选择材料、等待目标；
4. 三合一危险或就绪状态；
5. 当前页面的上下文操作提示。

普通制作当前没有专属 receipt，不得伪造“制作成功/失败”细节；它只显示既有 pending/saved/error 通用保存状态。若未来需要专属制作结果，必须先增加权威数据合同，不得从 draw 时序猜测。

状态栏左侧显示状态，`action_bounds` 显示当前页面唯一动作，右侧显示简短操作提示。装备页动作是现有“三合一（n/3）”，启用条件仍为配方 ready、无保存 pending 且 authority 可用；技能页动作是“取出”；材料页没有独立动作时隐藏该区域。底板始终 alpha 255；颜色只修饰边线、图标或文字，不以颜色作为唯一状态信号。保存锁定时所有会发 authority request 的控件显示禁用态，但页签切换和查看详情仍允许。

## 视觉语言与无障碍约束

- 背景：近黑蓝；主要面板：单层不透明深钢色；分隔线：低饱和古金；
- 选中青、配方品红、材料目标暗金、成功绿、危险珊瑚红；
- 所有文字底板 alpha 255，继续使用现有对比度回退；
- 文本不能仅靠颜色表达状态，必须同时有边框粗细、角标、标题或状态词；
- 正文和提示最小 12px，标签优先省略而不是继续缩小；
- Shared CJK 字体未就绪时不回退 `GetFontDefault`，整个文字层 fail-closed，避免中文方框。

## 数据流与代码边界

### 纯 View/布局层

`inventory_view_math.hpp/.cpp` 负责：

- `InventoryShellLayout`、三页内容布局、角色剪影槽位布局；
- `InventoryEmptyState`；
- tooltip 候选布局；
- `InventoryStatusPresentation` 优先级；
- 非零属性差异行的固定容量展示模型；
- 当前点击/筛选/配方/cache 的既有纯逻辑。

新增的 shell/empty/tooltip/status/diff builder 不调用 raylib 绘制、不访问全局输入且稳态不分配。既有 cache 刷新继续保留 `std::vector` 的受控容量增长，不把它错误纳入逐帧零分配声明。

### 渲染与 presentation 状态

`inventory_renderer.hpp/.cpp` 只负责：

- 当前页、选中、悬停、滚动和既有 presentation selection；
- 将纯 layout/view 画成现有 material + 图元；
- 把命中结果转换为既有 runtime request；
- 在素材绘制后统一叠加语义框和角标。

`material_bag_renderer.hpp/.cpp` 接收调用方提供的材料内容 bounds，不再反向调用旧三列 `inventory_layout()` 推导位置。

`ui_typography.hpp` 仅在确有必要时增加 `compact_min=12` 和 `hint=14` token；不修改全项目已有字号含义。

## 错误处理与安全边界

- 非有限 viewport、内容 bounds、测量结果或候选坐标：layout/view 不可见或 `valid=false`；
- 无效 item/base/affix/material id：跳过对应条目，不猜测英文 fallback；
- 未来非支持尺寸或无效输入下 tooltip 无合法候选：不显示，不覆盖状态栏或写出 viewport；三个支持分辨率必须满足前述保证候选；
- UTF-8 只通过现有安全 fit/format 写入固定缓冲，不使用裸 `snprintf` 截断玩家可见中文；
- 素材失败时使用同尺寸图元 fallback，语义 overlay 仍必须绘制；
- 请求 pending 或 authority disabled 时只禁用动作，不清空选中/筛选/页签；
- 不改变存档 schema，`hovered_item_id_`、当前页和 tooltip 均为易失 presentation 状态。
