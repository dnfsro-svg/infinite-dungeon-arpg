# 全量中文界面与高对比度布局设计

日期：2026-08-09
状态：已确认方向，待实施
技术基线：C++17、raylib 6.0

## 1. 目标

本次把游戏内所有玩家可达界面统一为简体中文，并同时完成以下视觉整改：

1. 菜单选项、页签和操作按钮的文字在各自完整交互区域内水平、垂直居中。
2. 信息密集页面按内容重新分区，避免把大量选项压在一列小字号中。
3. 正文、辅助、选中、警告、错误和成功状态均使用明确的深色背板与高对比度文字。
4. 中文字体、测量、截断和渲染走同一条 CJK 路径，不允许出现缺字、乱码、半个 UTF-8 字符或英文回退页。
5. 不改变玩法、存档格式、稳定 ID、设置编码、键位语义或数值规则。

## 2. 范围

### 2.1 必须汉化

- 暂停根菜单、设置、按键捕获、退出确认及全部状态消息。
- HUD、控制提示、交互提示、房间状态、生态、波次、深渊、保存和恢复界面。
- 背包、装备栏、装备底材名、品质、属性、词缀、材料、合成、强化和确认弹窗。
- 被动树标题、节点展示名、收益、代价、状态、提示和保存反馈。
- 怪物类型、怪物词缀、战斗状态、死亡结算和拾取反馈。
- F1 调试面板中玩家实际能看到的标签和枚举值。
- 游戏窗口标题及启动器中的正式玩家文案。

### 2.2 允许保留的字面量

- 物理按键名：`Esc`、`Enter`、`F1`、`F12`、`Num1`、`W` 等。
- 数字、百分号和无法自然翻译的文件/路径片段。
- 内部日志、自动化验证输出、测试名称、源码标识符和文件名。

`HP`、`XP`、`LV`、`SAVE ERROR` 等玩家界面缩写不在白名单内，分别显示为“生命”“经验”“等级”“存档错误”。

## 3. 不在本次范围

- 不增加英文/日文等语言切换功能。
- 不引入外部语言包、JSON 解析或运行时动态本地化系统。
- 不翻译内部存档键、枚举、物品 ID、被动节点 key、测试报告或 TraceLog 内容。
- 不改变装备、材料、怪物、技能、被动、掉落、战斗和保存规则。
- 不修改 V10 存档 wire、设置文件格式或版本号。

## 4. 方案选择

### 方案 A：散点替换

直接在各 renderer/view 中替换英文。改动表面最小，但会继续扩大重复字符串、漏翻风险和分散字形清单；当前字体计划已接近容量上限，无法可靠完成。

### 方案 B：通用多语言系统

引入语言代码、运行时语言包和通用 `TextId` 资源加载。可扩展性最高，但当前只要求简体中文，增加的运行时复杂度、失败模式和测试范围不成比例。

### 方案 C：静态中文展示目录（采用）

在 raylib 展示层建立静态中文目录和按稳定 ID 的展示映射。所有字符串与字形语料在编译期可枚举，无堆分配；核心数据仍保留原内部 ID 和英文 key。

## 5. 展示层文本架构

### 5.1 静态目录

新增 `src/platform/raylib/ui_text_catalog.hpp/.cpp`：

- `UiTextId` 覆盖菜单、HUD、背包、被动树、深渊、死亡及 F1 标签。
- `ui_text(UiTextId)` 返回静态 UTF-8 字符串。
- 为稳定枚举提供纯展示映射：
  - `ui_item_base_name(BaseId)`
  - `ui_material_name(MaterialId)`
  - `ui_item_slot_name(ItemSlot)`
  - `ui_item_rarity_name(ItemRarity)`
  - `ui_passive_node_name(PassiveNodeId)`
  - `ui_monster_name(MonsterId)`
  - `ui_monster_affix_name(MonsterAffixId)`
  - `ui_monster_affix_short_name(MonsterAffixId)`
- 所有返回值为 `const char*` 或 `std::string_view`，不得引入逐帧分配。

核心目录中的稳定英文 key 不改。尤其是物品 ID、材料 stable ID、被动节点 `name`、怪物/词缀枚举和存档结构均保持原值。

### 5.2 结构化按键提示

现有 HUD 从英文 `control_hints.secondary` 反向搜索 `Interact`、`Inventory` 和 `Passive Tree` 来提取按键。汉化后该逻辑会失效。

改为由 `SettingAction` 直接查询 `binding_for()`，再通过 `stable_key_label()` 得到按键名。显示文案只负责渲染，任何玩法或提示逻辑都不得解析显示字符串。

### 5.3 UTF-8 安全

新增 `ui_utf8.hpp/.cpp`，提供：

- 严格 UTF-8 校验。
- 按完整码点复制和截断。
- 固定缓冲格式化后修复尾部，确保 NUL 终止且不留下半个字符。
- 非法输入以 `?` 替换并记录诊断，不发生越界。

控制提示、暂停行、HUD 短文本、物品详情和被动树 tooltip 的所有固定缓冲均使用这套边界函数。

## 6. 统一中文字体

### 6.1 所有权

新增宿主持有的 `SharedUiFont`：

- 窗口初始化后只调用一次 `LoadFontEx`。
- HUD、暂停菜单、死亡结算、背包、被动树、房间交互、恢复页和 F1 面板都借用同一个 `Font`。
- 各 renderer 不再单独加载或卸载同一字体。
- 关闭顺序固定为：renderer 停止借用，随后宿主卸载共享字体。

### 6.2 字形计划和预算

- 字体资产继续使用 `assets/fonts/NotoSansCJKsc-Medium.otf`。
- 字形来源由 `ui_text_catalog` 的完整语料统一生成，不再分别手工维护 HUD/死亡两套字符串。
- 固定最大容量初始设为 640 个去重码点；若真实语料超过容量，测试失败，不静默丢字。
- 源字号保持 96px。
- 单一字体图集实际占用不得超过 32 MiB。
- 正式运行只允许一个 UI CJK 图集实例；相比现有三份重复图集降低总资源占用。
- 初始化必须逐条验证目录覆盖。字体资产缺失或覆盖失败时不得切换到英文死亡页；应终止进入正式界面，并由启动器显示中文资源错误。

## 7. 页面布局

### 7.1 暂停根页与退出确认

- 标题、每个完整按钮行和页脚均水平、垂直居中。
- 删除当前只包住文字宽度的左贴黑色块。
- 每行使用完整交互区域的深色内底；选中行增加青蓝边框和能量高光。
- 根页文案：继续游戏、设置、退出游戏。

### 7.2 设置

当前 21 行设置以约 23px 行高挤在单页，不再沿用。

设置改为四层状态：

1. 设置主页：音频设置、显示设置、按键设置、恢复默认设置、应用、取消。
2. 音频设置：总音量、音效、音乐、环境音、界面音、返回。
3. 显示设置：窗口模式、垂直同步、拾取过滤、返回。
4. 按键设置：十个动作绑定和返回。

每行主值居中；草稿与已保存值不再拼成长句。只有值尚未应用时，在右侧显示小型“已保存：…”辅助标签。底部固定中文操作说明。

### 7.3 背包、装备与材料

- 面板标题、页签、筛选按钮、合成按钮、确认/取消按钮居中。
- 装备和材料条目采用图标靠左，中文名称与数量在剩余内容区居中。
- 属性详情是数据表，保持标签左对齐、数值右对齐；不得为追求“全部居中”破坏扫描效率。
- 详情按实际 `MeasureTextEx` 结果换行，不按字节长度猜测。
- 强化危险弹窗的标题、警告、问题和两个按钮均居中。

### 7.4 被动树

- 标题“被动星图”顶部居中；未分配点在左，关闭键在右。
- 节点短名称以节点圆心居中；长名称和完整收益只放在 tooltip。
- tooltip 标题、类型、收益、代价和操作提示全部使用共享字体。
- 选中、可分配、已分配、锁定、保存中、保存失败同时通过颜色、边框和文案区分。

### 7.5 HUD、交互和 F1

- HUD 保留左下生命/护盾/经验、顶部目标、右上生态等现有信息分区，不强制整体居中。
- 技能键帽固定宽度，显示“小键盘 1”等中文说明；技能名称在图标下居中。
- 世界交互标签、洞口、深渊和临时通知增加不透明深色背板或清晰阴影。
- F1 调试层使用共享 CJK 字体并重新排为两列或自适应换行，避免 1280px 宽度溢出。

## 8. 色彩与对比度

统一基础颜色：

| 用途 | 颜色 |
| --- | --- |
| 页面深色背景 | `#050910` |
| 面板内部背景 | `#0B1019` |
| 普通正文 | `#F8F6EE` |
| 辅助正文 | `#C2E5FF` |
| 选中文字 | `#D9F6FF` |
| 禁用文字 | `#C7D3DF` |
| 禁用内底 | `#1C2530` |
| 警告 | `#FFD276` |
| 错误/破坏 | `#FF9898` |
| 成功 | `#93F4A9` |

- 所有正文与实际背板的 WCAG 对比度不得低于 4.5:1。
- 颜色不能成为唯一状态信号；同时使用边框、图标或明确中文状态。
- 稀有度颜色保留现有普通/魔法/稀有体系，但文字仍需满足背板对比要求。
- 现有无文字 UI 素材继续复用，不重新生成资产。

## 10. 错误与恢复

- 设置保存忙、外部实例修改、存储冲突、回滚失败分别显示不同中文消息。
- 地城存档恢复页使用共享 CJK 字体，显示“需要恢复存档”等中文信息。
- 字体加载、字形覆盖、UTF-8、文本越界和对比度失败均在验证中作为发布阻断，不静默降级。
- 动态文本无法完整容纳时，先缩小到页面规定的最小字号；仍无法容纳时按完整码点截断并显示省略号，同时记录诊断。正式验收要求常规中文语料零截断。

## 11. TDD 和验收

### 11.1 自动化门禁

1. 全中文目录非空、UTF-8 合法，所有枚举值均有展示映射。
2. 玩家可见英文扫描只允许按键名和明确白名单。
3. 统一字形计划覆盖所有静态语料和动态格式样例；码点唯一且不超过容量。
4. 运行时 UI CJK 字体实例数为 1，实际图集不超过 32 MiB。
5. UTF-8 在 1/2/3/4 字节边界截断后仍合法、NUL 终止。
6. 暂停、设置、按键捕获和退出确认的交互行在三种分辨率下 X/Y 居中。
7. 背包数据表继续满足名称左对齐、数值右对齐。
8. 各状态色相对实际背板的对比度均不低于 4.5:1。
9. `ui_text_bounds_audit` 覆盖暂停、HUD、背包、技能、被动树、死亡和确认弹窗，常规场景无越界、遮挡和截断。
10. 设置、checkpoint、persistence 测试继续通过，证明显示层改动不影响格式和规则。

### 11.2 Windows 实机截图

在 800×450、1280×720、1920×1080 验收：

- 暂停根页、退出确认。
- 设置主页、音频、显示、按键和按键捕获。
- 空背包、有装备背包、材料袋、合成、强化危险弹窗。
- 被动树四路线、tooltip、可用/锁定/保存中/错误状态。
- HUD 普通战斗、波次、深渊、低血、拾取和保存通知。
- 四生态门、洞口和深渊交互。
- 死亡结算、保存失败和存档恢复。
- F1 调试面板。

每张截图必须满足：无玩家可见英文残留、无方块、无乱码、无文字越界或重叠、选项居中、文字/背板对比清晰。
