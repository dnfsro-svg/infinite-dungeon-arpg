# 桌面游戏启动器设计

日期：2026-07-25

状态：待用户复核

目标平台：Windows x64

项目版本：0.1.0

## 目标

为《无限地下城》提供一个资源占用低、中文清晰、可从桌面直接启动的独立图形启动器。启动器不改变游戏玩法，不替代游戏内设置，只负责验证本地游戏文件、启动游戏和打开存档目录。

## 不在范围内

- 不实现账号、密码或联网登录。
- 不实现在线更新、广告、公告和遥测。
- 不修改游戏存档格式、战斗逻辑或图形设置。
- 不在启动器后台常驻。

## 技术方案

新增原生 Win32 C++17 目标 `arpg_launcher`，不依赖 raylib 或 .NET。窗口使用无控制台的 Windows GUI 子系统，高 DPI 感知，并使用 Direct2D/DirectWrite 绘制深色金属界面和清晰中文文本。

启动器代码拆成两层：

1. `launcher_core`：纯 C++ 路径解析、文件状态、启动参数和状态文本，可在单元测试中运行。
2. `launcher_win32`：窗口、按钮、绘制、文件夹打开和进程启动，仅负责平台交互。

这种边界保证路径与命令行为可以自动验证，同时不把 Win32 界面代码混入游戏运行时。

## 部署布局

部署脚本接收一个明确的 `-GameBuildDirectory` 参数，只接受包含
`arpg_game.exe` 与 `assets` 的 Release 输出目录；路径无效时直接失败，
不会回退到其他工作树或旧构建。脚本生成以下结构：

```text
%LOCALAPPDATA%\InfiniteDungeon\app\
  无限地下城启动器.exe
  arpg_game.exe
  assets\

%USERPROFILE%\Desktop\
  无限地下城.lnk
```

桌面快捷方式指向已部署的启动器，并使用启动器图标。游戏继续使用现有默认存档目录 `%LOCALAPPDATA%\InfiniteDungeon\save`，因此不会新建不兼容的存档位置，也不会丢失已有进度。

启动器只从自身目录寻找 `arpg_game.exe` 和必要的 `assets` 子目录，不硬编码工作树或构建目录。部署时从已验证的 Release 输出复制游戏程序与资源。

## 界面

窗口采用固定 920×560 逻辑像素、不可拖拽缩放，并随系统 DPI 等比例缩放：

- 顶部：`无限地下城`、版本号和简短副标题。
- 中部：游戏文件状态，成功时显示纯绿色“游戏已就绪”，失败时显示纯红色原因。
- 主操作：醒目的 `开始游戏` 按钮。
- 次操作：`检查游戏文件`、`打开存档目录`、`退出`。
- 底部：实际游戏路径；过长时截断显示，但鼠标悬停可查看完整路径。

字体优先使用系统的 Microsoft YaHei UI，通过 DirectWrite 按当前 DPI 渲染。文字使用纯色，不使用纹理内文字、透明叠色或模糊缩放。按钮和文本布局以测量后的实际边界为准，禁止相互覆盖。

## 行为流程

### 启动时

1. 取得启动器自身目录。
2. 验证同目录的 `arpg_game.exe`。
3. 验证 `assets/fonts`、`assets/player`、`assets/skills`、`assets/stage12`、`assets/stage14/audio` 和 `assets/stage15/audio`。
4. 更新状态；文件不完整时禁用 `开始游戏`。

### 开始游戏

1. 重新检查文件状态，避免启动前文件被移动。
2. 用 `CreateProcessW` 启动同目录的 `arpg_game.exe`，工作目录设为应用目录，不额外传入存档参数。
3. 创建成功后立即关闭启动器，不在后台占用资源。
4. 创建失败时保留窗口，并显示 Windows 错误信息。

### 打开存档目录

若 `%LOCALAPPDATA%\InfiniteDungeon\save` 不存在，则先创建；随后使用资源管理器打开。失败时在界面内显示原因。

### 检查游戏文件

重新执行启动时的验证并刷新状态。这里只验证必须文件和目录存在，不宣称提供密码学完整性或自动修复。

## 错误处理

- 缺少游戏程序：显示“缺少 arpg_game.exe”。
- 缺少资源目录：逐项显示首个缺失目录，并保持启动按钮禁用。
- 环境变量不可用：显示存档目录不可用，不崩溃。
- 游戏启动失败：显示系统错误码和可读错误消息。
- 所有路径均使用宽字符 Windows API，支持中文和空格。

## 验证

自动测试至少覆盖：

- 从启动器路径解析同目录游戏路径。
- 识别完整、缺少程序和缺少资源三种文件状态。
- 构造的启动请求不包含验证专用参数，并使用正确工作目录。
- 解析默认存档目录。
- 长路径与中文路径不会被窄字符转换破坏。

本地验收包括：

- Debug 与 Release 构建成功。
- 启动器单元测试和项目现有 CTest 全部通过。
- 以 100%、125%、150% 和 200% DPI 检查文字清晰度与边界不重叠。
- 从桌面快捷方式启动实际 Release 游戏。
- 验证启动后启动器进程退出、游戏进程运行、默认存档目录未改变。
- 临时移走一个必需资源目录，验证启动被阻止并出现明确错误，然后恢复现场。

## 完成标准

- 桌面存在可双击的 `无限地下城.lnk`。
- 启动器界面中文清晰、纯色、无重叠。
- 完整文件状态下可启动当前 Release 游戏。
- 文件缺失时不会错误启动。
- 启动器不常驻、不修改游戏玩法、不更改现有存档位置。
