# Stage 8 装备与掉落 MVP 设计

日期：2026-07-14  
分支：`codex/stage8-equipment-loot-mvp`  
基线：已验收 Stage 7，提交 `352cc13`

## 1. 目标

Stage 8 交付可在现有无限地下城中实际使用的装备闭环：怪物死亡时低概率生成地面装备，玩家靠近自动拾取，在暂停式三栏背包中查看、装备、卸下和三合一，并把所有稳定状态原子保存。装备复用现有 Modifier 体系，立即改变当前战斗属性，同时保证重载不能重骰、复制或恢复已消耗材料。

本阶段固定实现：

- 6 个装备部位：武器、头盔、胸甲、手套、鞋子、饰品。
- 每个部位 1 个固定基底；首版只有 1 种武器基底，不增加独立招式。
- 物品等级与需求等级均为 1～100，且是两个独立字段。
- 普通、魔法、稀有三种稀有度。
- 12 条前缀、12 条后缀，共 24 条装备词缀。
- T1～T8 完整词缀阶级，T1 最强。
- 每件装备最多 3 前缀和 3 后缀。
- 无玩法容量上限的背包、6 槽装备状态和三合一。
- 地面装备、靠近自动拾取、即时换装、闪避、护甲和四元素伤害减免。
- 可变长度 V4 存档与 V1～V3 迁移。

## 2. 明确不做

Stage 8 不实现：

- 史诗装备与改变技能机制的装备。
- 品质、强化、工艺、污秽、鉴定、耐久、材料、商店或分解。
- 单件销毁功能。
- 物品过滤器、地面物品隐藏规则或自动补收。
- 多种武器动作、主动技能、暴击、异常、穿透、吸取或伤害转换。
- 怪物词条、正式精英层级、深渊专属装备或 Stage 9 内容。
- 背包玩法容量；只保留存档解码安全边界。

## 3. 模块边界

新增无图形静态库 `arpg_items`，只依赖 `arpg_modifiers`：

- `items` 拥有基底目录、词缀目录、阶级表、稀有度、生成、合法性验证、三合一规则和装备 Modifier 投影。
- `modifiers` 增加物理固定伤害、护甲值、闪避值和四元素伤害减免上限等通用 Stat；既有 resistance 命名改为 damage reduction，数值语义保持兼容。
- `combat` 只消费汇总后的 `PlayerModifierValues`，不依赖 `items`。它负责闪避判定、护甲物理减伤、按类型减伤和当前生命/护盾截断。
- `dungeon` 拥有稳定物品表、6 个装备 ID、当前房间已领取掉落位图、地面掉落实例及拾取、换装和合成事务。
- `persistence` 只编码、验证和轮换完整检查点，不生成或重算词缀。
- raylib 负责地面图标、拾取反馈、三栏背包、输入门控和物品比较，不拥有物品规则。

`core`、`combat`、`modifiers`、`items`、`dungeon` 和 `persistence` 不得依赖 raylib。战斗热路径不得因装备数量进行背包遍历或堆分配；装备汇总只在加载、拾取后的稳定提交、换装或合成时重算。

## 4. 核心数据

```cpp
enum class ItemSlot : std::uint8_t {
    weapon, helmet, chest, gloves, boots, accessory, count
};

enum class ItemRarity : std::uint8_t {
    normal, magic, rare
};

struct AffixRoll final {
    std::uint16_t affix_id{};
    std::uint8_t tier{};      // 1..8
    std::uint8_t variant{};   // 上限词缀的元素；其他词缀固定为 255
};

struct ItemInstance final {
    std::uint64_t id{};
    std::uint8_t base_id{};
    ItemRarity rarity{};
    std::uint8_t item_level{};
    std::uint8_t required_level{};
    std::array<AffixRoll, 6> affixes{};
    std::uint8_t affix_count{};
};

struct EquipmentState final {
    std::array<std::uint64_t, 6> equipped_ids{}; // 0 表示空槽
};
```

检查点拥有一个按获得顺序保存的 `std::vector<ItemInstance>`。已装备物品仍在该唯一物品表内，`equipped_ids` 只引用它们；不存在第二份装备副本。界面把未被装备槽引用的记录显示为背包物品。

游戏内不显示背包容量上限。解码器最多接受 65,535 件物品；该限制只用于防止损坏存档造成越界、超大分配或整数溢出。

掉落物品 ID 由 `root_seed + room_index + drop_ordinal + drop 域` 派生；三合一产物 ID 由持久化的 `next_item_sequence + root_seed + recipe 域` 派生。ID 必须非零；哈希结果为零时使用固定非零重映射。任何新 ID 与当前物品表冲突都进入 faulted，不允许换种子重骰。三合一词缀种子仍只由排序后的三个材料 ID 与 recipe-affix 域派生，因此相同材料重试得到相同词缀。

物品名称不另存文本：普通显示基底名，魔法显示“魔法 + 基底名”，稀有显示“稀有 + 基底名”。Stage 8 不生成随机物品名称。

## 7. 稀有度与词缀生成

物品等级固定为：

```text
item_level = min(100, current_depth)
```

令 `x = item_level - 1`，稀有度整数百分比为：

```text
normal = 70 - floor(30 * x / 99)
magic  = 25 + floor(15 * x / 99)
rare   = 100 - normal - magic
```

因此物品等级 1 为普通 70% / 魔法 25% / 稀有 5%，物品等级 100 为普通 40% / 魔法 40% / 稀有 20%。

词缀数量：

- 普通：0 条。
- 魔法：1 条与 2 条各 50%。
- 稀有：3/4/5/6 条权重依次为 40/30/20/10。
- 前缀、后缀各不超过 3 条。
- 生成器必须先证明目标部位存在足够合法候选，再逐次按权重无放回抽取；不能因后抽词缀冲突而静默减少目标词缀数。

阶级资格由第 5 节门槛决定。已解锁阶级的基础权重从 T8 到 T1 为：

```text
64, 48, 36, 27, 20, 15, 11, 8
```

在基础权重上，当前最高可用阶级增加 `floor(item_level / 5)`，第二高可用阶级增加 `floor(item_level / 10)`；只有一个可用阶级时只加第一项。所有权重使用整数无偏有界随机抽取。

需求等级取已生成词缀中最强阶级的最低物品等级门槛；普通装备没有词缀，需求等级固定为 1。需求等级不得由物品等级直接覆盖。

## 8. 属性求值

武器附加物理伤害按以下顺序计算：

```text
weapon_physical = floor(
    (base_weapon_physical + local_flat_physical)
    * (10000 + local_physical_increased_bp) / 10000)
```

该值作为固定物理分量添加到 J/K/L 每次有效近战命中。四种固定元素伤害作为独立伤害分量，先应用同元素 increased，再进入目标减伤。

装备、星盘和瞬时 Effect 的全局 Modifier 仍按现有 flat → increased → more 顺序求值。装备不得改变攻击有效帧；攻速仍只缩放前摇与后摇，保持现有 Stage 7 语义。

换装保存成功后立即重新求值当前角色：

- 当前生命保持绝对值；只在超过新最大生命时截断。
- 当前护盾保持绝对值；只在超过新最大护盾时截断。
- 增加生命或护盾上限不回复生命或补充护盾。
- 卸下武器后仍能使用既有 J/K/L，但不再获得武器附加伤害和局部攻速。

## 9. 闪避、护甲与元素伤害减免

### 9.1 共用数值曲线

闪避值与护甲值使用同一单调曲线，结果以基点表示：

| 数值 | 效果基点 | 显示值 |
|---:|---:|---:|
| 0 | 0 | 0% |
| 100 | 2,000 | 20% |
| 1,000 | 4,000 | 40% |
| 10,000 | 6,000 | 60% |
| 100,000 | 8,000 | 80% |
| 1,000,000 | 9,900 | 99% |
| 10,000,000 | 9,990 | 99.9% |

锚点之间使用 64 位整数分段线性插值，精确命中全部锚点。超过 10,000,000 后：

```text
gap_bp = max(1, ceil(100000000 / value))
result_bp = 10000 - gap_bp
```

因此结果永远小于 100%，并在高数值区快速接近 99.99%。所有乘法必须使用 checked/saturating 64 位中间值，负数值非法。

### 9.2 闪避

- 近战、投射物、冲锋等具有直接命中语义的攻击可闪避。
- 地面持续伤害、环境伤害和已经生效的持续伤害不能闪避。
- 一个混合类型伤害包只投掷一次闪避；成功时整个伤害包为零。
- 闪避使用战斗独立随机流；同一固定种子和输入 trace 必须得到相同结果。
- 没有可闪避伤害时不得消费闪避随机数。

### 9.3 护甲

护甲曲线得到的减伤率只作用于物理伤害分量，不改变火、水、电或混沌伤害。

### 9.4 四元素伤害减免

原有 fire/water/lightning/chaos resistance 在代码、HUD 和物品文案中统一改名为对应元素 `damage reduction rate`。存档不直接保存这些派生值，因此无需数值迁移。

- 每种元素基础允许范围为 -60%～75%。
- 负值表示承受更多对应类型伤害。
- 词缀 112 可以提高指定元素上限；绝对上限 95%。
- 对每个非零伤害分量使用向上取整，保证上限低于 100% 时非零原始伤害不会因整数截断变为零。

```text
final_element_damage = ceil(
    raw_element_damage * (10000 - clamped_reduction_bp) / 10000)
```

物理分量使用护甲曲线；四元素分量各自只应用一次对应减免率，不再叠加另一套“抗性”乘区。

## 10. 掉落与地面物品

每个房间最多有 2 波，每波最多 96 个稳定出生序号。稳定怪物掉落序号为：

```text
drop_ordinal = wave_index * 96 + spawn_index  // 0..191
```

怪物死亡时使用独立物品掉落随机域，由当前房间种子和 `drop_ordinal` 派生。每只怪物只进行一次：

```text
uniform_bounded(100) == 0  // 1%
```

- 每个怪物最多生成 1 件装备。
- 不设置额外房间掉落件数上限。
- 地面掉落池容量固定为 192，等于当前房可生成的稳定怪物总上限。
- 物品部位 6 种等权；随后按第 7 节生成稀有度和词缀。
- 地面物品出现在怪物死亡 X/Y 位置，Z 固定为地面；玩家在 X/Y 距离 1.5 个世界单位内自动请求拾取。
- 离开房间时所有未拾取装备永久销毁，不自动补收。该规则是对旧“重要奖励必须自动收取”基线的用户明确修改。

地面表现只显示部位与稀有度颜色，不提前泄露不存在的鉴定状态。所有拾取装备立即显示完整词缀。

## 11. 拾取与防复制

当前检查点保存 192 位 `claimed_drop_bits`。地面掉落本身是当前房瞬时状态，不完整写入存档。

拾取事务：

1. 验证当前掉落仍存在、序号未领取、物品 ID 不冲突且物品合法。
2. 构造下一稳定检查点：追加完整物品记录并设置对应领取位。
3. 提交 V4 检查点。
4. committed 后才从地面池移除物品并向 UI 显示已拾取。
5. not_committed 保持地面物品和旧背包不变，允许重试。
6. indeterminate 进入现有 faulted 流程，禁止继续拾取、换装、合成或离房。

重载当前房后，已领取序号即使对应怪物再次生成，也不得再次掉落；未领取装备可以在重新击败相同稳定怪物后按同一内容重新出现。房间切换 committed 后，领取位对新房清零。

## 12. 背包、换装与三合一

### 12.1 三栏界面

按 `I` 打开或关闭背包。打开时暂停固定步战斗模拟，屏蔽移动、J/K/L、E、P 和门/洞请求；菜单 UI 仍更新。

- 左栏：6 个装备槽和角色汇总属性。
- 中栏：虚拟化背包网格，只为当前可见格生成绘制项；默认按获得顺序显示，可按全部/部位/稀有度筛选。
- 右栏：物品等级、需求等级、基底固有属性、全部词缀、局部/全局标签及与当前装备的属性差异。
- 单击背包物品查看；双击请求装备。
- 单击已装备物品请求卸下。
- `Ctrl + 左键`切换三合一选择；最多选择 3 件。
- `Esc` 或 `I` 关闭界面并恢复战斗。

界面不提供拖拽、鉴定、销毁、分解、排序写回或物品过滤器。

换装差异必须分别求值“当前完整 build”和“替换后的完整 build”再做差，不能把词缀文本简单相加；闪避、护甲、减免上限、局部武器属性和 more/less 乘区因此都能正确比较。

### 12.2 换装事务

换装和卸下在任何房间阶段都可通过暂停式背包请求，但以下状态拒绝：已有 pending save、runtime faulted、存档恢复画面或目标物品等级需求未满足。

事务先构造新的 6 槽引用并验证每个 ID 唯一、部位匹配和物品存在，再保存完整检查点。只有 committed 后才把新 build 应用到当前 `CombatWorld`。not_committed 保持旧装备和旧战斗 build；indeterminate 进入 faulted。

### 12.3 三合一

三件材料必须：

- 都存在于唯一物品表。
- 都未装备。
- ID 两两不同。
- 部位相同。
- 稀有度相同。

产物规则：

- 部位和稀有度保持不变。
- 每个部位只有一个基底，因此基底由部位确定。
- `item_level = floor((a.item_level + b.item_level + c.item_level) / 3)`。
- 普通产物仍为 0 词缀；魔法/稀有按第 7 节重新生成目标词缀数和全部词缀。
- 词缀随机种子由排序后的三个材料 ID 和固定 recipe 域派生。
- 产物获得新的稳定 ID；材料删除、产物追加和下一 ID 更新属于同一个检查点。

committed 前 UI 保持三件材料。not_committed 不消费材料且不改变预览；相同材料重试得到同一产物。indeterminate 进入 faulted。Stage 8 不提供其他减少背包物品的方法。

## 13. V4 存档

V4 使用 magic `IARPGS05`、format version 4、rules version 1 和现有 32 字节头。CRC 覆盖头部稳定字段和完整可变 payload；编码器改为有界动态字节缓冲，不使用固定 120 字节数组。

V4 payload 前 88 字节保持 V3 稳定字段编码顺序，随后追加：

| 相对 payload 偏移 | 字段 | 大小 |
|---:|---|---:|
| 88 | item_count | 4 |
| 92 | next_item_sequence | 8 |
| 100 | claimed_drop_bits[0..2] | 24 |
| 124 | equipped_ids[0..5] | 48 |
| 172 | item_records | `item_count * 40` |

总 payload 大小为 `172 + item_count * 40`，总文件大小为 `204 + item_count * 40`。所有整数小端编码；payload 长度必须 checked 计算并与文件长度完全相等。

每个 40 字节物品记录：

| 相对记录偏移 | 字段 | 大小 |
|---:|---|---:|
| 0 | item_id | 8 |
| 8 | base_id | 1 |
| 9 | rarity | 1 |
| 10 | item_level | 1 |
| 11 | required_level | 1 |
| 12 | affix_count | 1 |
| 13 | reserved，必须为 0 | 3 |
| 16 | 6 个 AffixRoll，每个 4 字节 | 24 |

未使用 AffixRoll 的 4 字节必须全为 0；已使用记录编码 `affix_id:u16, tier:u8, variant:u8`。

V1、V2、V3 解码后迁移为：空物品表、空装备、领取位全 0、`next_item_sequence = 1`，其他地下城、进度和星盘字段保持。V4 加载必须拒绝：

- 物品数超过 65,535、长度溢出或尾随字节。
- 0 或重复物品 ID。
- 非法基底、稀有度、物品等级、需求等级、词缀数、阶级或 variant。
- 普通装备含词缀、魔法词缀数不为 1～2、稀有词缀数不为 3～6。
- 前/后缀超过 3、词缀组重复、部位不允许或需求等级与最强阶级不一致。
- 装备 ID 不存在、部位不匹配或同一 ID 出现在两个槽。
- 元素减免上限投影超过 95% 或任何求值溢出。

## 14. 输入与房间状态

- `I` 在正常运行状态均可打开背包，包括战斗中；打开后整个 fixed-step 模拟暂停。
- 打开背包时清空 fixed-step 累积余量；背包打开期间不调用 `advance()`；关闭后从零余量恢复，禁止把菜单停留时间补跑成大量逻辑 tick。
- 背包打开时不能打开星盘；星盘打开时 `I` 不能打开背包。
- 背包打开时不能选择门、洞、重置房间或排队攻击。
- 拾取只在背包关闭且战斗模拟推进时检测距离。
- pending save 时禁止新的拾取、换装、卸下、合成、门和洞请求。
- 离房 committed 时销毁地面掉落池；不把未领取物品加入背包。

### 15.2 窗口验收

1. 击杀怪物直到观察到地面装备，确认部位和稀有度可读。
2. 靠近后自动拾取，按 `I` 确认战斗暂停和三栏布局。

4. 更换生命和护盾装备，确认当前值只截断、不回复。
5. 选择 3 件同部位同稀有度未装备物品完成合成，确认材料消失且产物出现。
6. 留下一件未拾取装备并离房，确认它随旧房永久消失。
7. 重启游戏，确认背包、装备、属性、合成产物和领取状态保持。
