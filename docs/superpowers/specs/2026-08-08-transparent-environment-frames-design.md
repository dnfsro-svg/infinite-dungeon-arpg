# CPLAY-019 透明环境门与洞口材质设计

## 目标

消除元素门和深渊洞口周围的方形墙面/地板背景，保留现有元素语义、世界尺寸、碰撞、门位置、atlas ID、帧坐标和渲染接口。

## 已确认根因

- 渲染器正常绘制 manifest 的完整帧；shader 正常相乘色图和 material map 的 alpha。
- 现有水/雷/混沌门与多个生态洞口本身就包含近乎不透明的房间地面/墙面。
- 现有构建脚本只删除接近边缘中位色的像素；渐变石墙和地板与主体连通，因此会被保留为大矩形。

## 方案对比

### A. 从现有高分辨率键色源确定性重建（采用）

- 门使用 `art_source/stage12/door-concept-v1.png`。
- 洞口使用 `art_source/stage12/abyss-hole-concept-v1.png`。
- 先对鲜色键色背景生成透明 alpha，再用确定性色相/明度参数生成火、水、雷、混沌变体。
- 色图与 material map 共用完全相同的 alpha mask。
- 保持现有 256×256 帧尺寸、atlas 顺序与 manifest，运行时无新分支。

### B. 继续清理现有合成帧（不采用）

需要为每张地面和墙面反复调阈值，容易留下暗边、光晕矩形或误删主体，四种元素也难以保持一致轮廓。

### C. 运行时 shader 掩码（不采用）

污染背景和主体都是不透明像素，shader 没有可靠的语义边界；会增加每帧复杂度且仍无法保证视觉结果。

## 数据流与范围

1. `tools/build_environment_props.py` 读取两张现有键色源。
2. 生成单一透明轮廓，完成四元素调色。
3. 组装回现有 `element_doors` 及各生态洞口帧位，同步 material map alpha。
4. 更新构建报告 schema/来源标识，禁止旧错误哈希直接复用。
5. 运行时 selector、renderer、碰撞和玩法代码不改。

本子卡只修复方形背板的门与洞口。混沌普通环境小物件的语义映射问题单独记录，不与本次透明度修复捆绑。

## 验收

- 每帧四周有安全透明边距。
- alpha bbox 内不允许近乎全宽/全高的连续不透明横行或纵列，不允许近乎实心的大矩形。
- 色图与 material map alpha 逐像素一致。
- 四元素门与相关洞口在 1280×720 安装版画面中无方形墙地背板、无贴图越界，主体轮廓清楚。

## 验证边界

- 先用 Python 资产管线单测观察 RED，再实施并运行同一窄测 GREEN。
- manifest 和 C++ selector 不变时，不跑全量平台/地下城测试。
- 最后只构建一次 Release，部署后用内部 F12 截图做 Windows 视觉验收，验收后立即关闭游戏。
