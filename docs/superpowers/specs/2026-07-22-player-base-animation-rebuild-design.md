# 玩家基础动作材质重制设计

## 目标

把玩家从单帧角色贴图切换为原创的、按动作逐帧播放的 2.5D 动画包；不触碰战斗判定、输入、存档与技能石规则。

## 已确认约束

- 视觉：暗钢盔甲、古金边饰、阔刃实体剑、蓝白能量；不使用光剑或任何 DNF 原图。
- 逻辑仍以 60 Hz 推进；显示动画为 24 fps；每个动作的有效帧必须拥有不同 UV 与感知哈希。
- 最低有效帧：待机 16、移动 20、跳跃 24、J1/J2/J3 为 18/22/26、L 上挑 24、受击 10、倒地 16、起身 14、死亡 24。
- 动画帧使用脚底锚点和独立武器锚点；所有普通玩家贴图均来自当前生态无关的公共玩家包。

## 方案比较

1. 继续复用 `actors.png` 并伪造帧索引：改动小，但不满足有效帧与原创动作要求，淘汰。
2. 为每种动作各建图集：最直观，但纹理切换多、包管理复杂，淘汰。
3. 五张 8×8 动作表：每张 1024×1024、128 像素单格，运行时只持有公共玩家包；可容纳 320 格并以固定容量索引播放，采用。

## 资源分组

| 图集 | 动作 | 有效帧 |
| --- | --- | ---: |
| `player_locomotion.png` | 待机、移动、跳跃 | 60 |
| `player_combo_a.png` | J1、J2 | 40 |
| `player_combo_b.png` | J3、L 上挑 | 50 |
| `player_reaction.png` | 受击、倒地、起身、死亡 | 64 |
| `player_air.png` | 空中 J、落地与预留转场 | 32 |

## 运行时边界

`PlayerAnimationSelector` 只把 `PlayerState` 与 `AttackId` 投影为 `PlayerAnimationClipId`。`MaterialPack` 依据帧定义绘制对应 UV；`ActorRenderer` 以战斗快照 tick 驱动 24 fps 帧索引。渲染端不得回写战斗状态，战斗端不得了解 raylib 纹理。

## 验收

单元测试必须拒绝复用 UV、帧数不足、越界锚点与缺失颜色图。真实 Raylib 验收在 1280×720 窗口依次截取待机、移动、J1、J2、J3、上挑、跳跃、受击、倒地、起身与死亡，并确认相邻帧像素不相同。
