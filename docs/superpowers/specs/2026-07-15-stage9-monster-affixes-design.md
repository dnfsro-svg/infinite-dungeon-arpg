# Stage 9 怪物词缀系统设计

日期：2026-07-15
分支：`codex/stage9-monster-affixes`
基线：已验收 Stage 8，提交 `7b54370`

## 1. 目标

Stage 9 在现有 8 种怪物、确定性房间生成、固定容量战斗和装备掉落系统上增加首批 12 个怪物词缀。词缀必须可独立组合、可扩展到 24/40/72 条、具有明确预警和风险奖励，并保证相同房间种子、波次与出生序号生成完全一致。

本阶段固定实现：

- 首批 12 个词缀，每个词缀拥有稳定 ID、标签、生成权重、M1～M3 数值、危险级、适用标签、视觉和声音提示。
- 每只怪物独立抽取 0～3 条不重复词缀，不使用房间危险预算或高危数量上限。
- 深度提高词缀数量和 M1～M3 权重。
- 仅禁止机制互斥、适用性不匹配或理论无解的组合；允许三高危等极端组合。
- 带词缀怪物按危险分增加经验、直接装备掉落概率和有效物品等级。
- 词缀由数据表和通用效果原语组成，不为每条词缀建立独立类。
- 完整血条标识、颜色描边、高危脉冲图标和声音预警。

## 2. 明确不做

Stage 9 不实现：

- 第 13 条及后续怪物词缀。
- 深渊专属词缀、正式深渊房间或 Stage 10 内容。
- 新怪物种类、正式精英怪层级或房间危险预算。
- 新装备词缀、装备界面改版、鉴定或其他装备玩法。
- 召唤、强化光环、生命回复等未进入首批 12 条的机制。
- 长期平衡终稿；本设计数值是首轮可玩基线，验收后可单独调参。

## 3. 模块边界

在现有无图形 `arpg_combat` 静态库内新增独立 `combat/monster_affixes` 子模块，复用既有 `MonsterId`、`MonsterTag`、确定性随机和 Modifier/Effect 原语，不依赖 raylib。这样避免把现有怪物类型搬到新库后造成 `combat` 与 `dungeon` 的依赖环：

- `combat/monster_affixes` 拥有词缀目录、定义验证、深度概率、适用性过滤、确定性抽取、危险分和通用运行时状态。
- `dungeon` 的遭遇导演为每个 `MonsterSpawnSpec` 生成最多 3 个词缀实例；基础怪物选择、出生位置和波次随机流保持不变。
- `combat` 消费已生成的词缀实例，应用属性投影、命中/定时/死亡触发和对象清理；不自行重骰词缀。
- `dungeon` 会话消费击杀事件携带的危险分，计算额外经验、直接掉落概率和有效物品等级。
- raylib 只消费战斗快照，绘制词缀文本、描边、预警并播放提示音，不参与规则判断。
- `persistence` 不重复保存可由房间种子推导的词缀；现有物品表、领取位图和原子保存语义保持不变。

所有运行时集合使用固定容量。战斗热路径不得因词缀数量进行堆分配、字符串查找或背包遍历。

## 4. 核心数据

建议核心形状如下，最终字段名可在实施计划中按现有代码风格调整：

```cpp
enum class MonsterAffixId : std::uint8_t {
    mighty,
    frenzy,
    swift,
    armored,
    shielding,
    multishot,
    burning_ground,
    chilling,
    chain_lightning,
    chaos_corrosion,
    blink_assault,
    death_blast,
    count,
};

enum class MonsterAffixTier : std::uint8_t { m1 = 1, m2, m3 };
enum class MonsterAffixDanger : std::uint8_t { low = 1, medium = 2, high = 3 };

struct MonsterAffixInstance final {
    MonsterAffixId id{};
    MonsterAffixTier tier{MonsterAffixTier::m1};
};

struct MonsterAffixSet final {
    std::array<MonsterAffixInstance, 3> values{};
    std::uint8_t count{};
};
```

`MonsterAffixDefinition` 数据表至少包含稳定 ID、名称/简称、类别标签、危险级、基础权重、必需/禁止怪物标签、冲突组、M1～M3 参数、视觉类别、声音提示和通用效果描述。目录必须编译期或启动时验证：ID 连续唯一、权重非零、等级参数合法、标签不矛盾、危险级合法。

词缀实例和稳定 `spawn_ordinal` 进入 `MonsterSpawnSpec`，随后复制到 `MonsterRuntime` 和只读快照。单只怪物不得重复同一词缀 ID；击杀事件直接携带 `spawn_ordinal`，不把运行时池下标误当成稳定掉落序号。

## 5. 确定性生成

词缀生成使用独立随机域，由以下稳定输入派生：

```text
room_seed + wave_index + spawn_index + monster_affix_domain
```

基础遭遇计划先按 Stage 4 既有随机域完成；词缀生成后置执行，因此增加词缀不得改变怪物类型、数量、波次和位置。词缀数量、每条词缀选择和每条等级选择使用彼此独立的子域，避免新增一次抽样改变其他结果。

每只怪物独立抽取词缀数量：

| 地下城深度 | 0 条 | 1 条 | 2 条 | 3 条 | M1 / M2 / M3 权重 |
|---|---:|---:|---:|---:|---:|
| 1～3 | 80% | 20% | 0% | 0% | 100 / 0 / 0 |
| 4～9 | 55% | 38% | 7% | 0% | 80 / 20 / 0 |
| 10～19 | 30% | 45% | 20% | 5% | 50 / 40 / 10 |
| 20～39 | 15% | 35% | 35% | 15% | 25 / 50 / 25 |
| 40+ | 5% | 20% | 40% | 35% | 10 / 35 / 55 |

抽取流程：

1. 根据深度抽取目标数量。
2. 依据怪物标签构造合法候选；多重投射只适用于真正发射弹体的怪，闪现突袭只适用于近战怪，命中附加类词缀只适用于具有直接攻击能力的怪。
3. 按定义权重无放回抽取，拒绝重复 ID、机制互斥和理论无解组合。
4. 候选不足时必须在目录验证或计划生成阶段报告错误，不得静默减少目标数量。
5. 每个已选词缀独立抽取 M1～M3。

首批 12 条没有高危数量上限。强壮、坚甲、护盾等耐久组合以及闪现、炽燃、死亡爆破等三高危组合都允许生成。

| 4 | 护盾 | 中 | 脱离受击后恢复可再生护盾 | 通用；保持压制 |
| 5 | 多重投射 | 高 | 远程攻击形成扇形多弹体 | 仅弹体型远程；寻找弹幕间隙 |

## 7. M1～M3 初始数值

数值按 Stage 8 基线中怪物生命 220～700、玩家基础生命 1000、怪物单次伤害 35～120 校准：

| 词缀 | M1 | M2 | M3 |
|---|---|---|---|
| 强壮 | `+30%` 生命，`15%` 抗击退 | `+60%`，`30%` | `+100%`，`45%` |
| 狂暴 | `+15%` 伤害，`+10%` 攻速 | `+30%`，`+20%` | `+50%`，`+30%` |
| 迅捷 | `+15%` 移速，技能间隔 `-8%` | `+30%`，`-16%` | `+45%`，`-24%` |
| 坚甲 | 目标物理减伤 `15%` | `25%` | `35%` |
| 护盾 | 最大生命 `20%` 的护盾，脱离受击 `3秒` 后恢复 | `35% / 2.5秒` | `50% / 2秒` |
| 多重投射 | 2 枚，每枚 `75%` 原伤害 | 3 枚，每枚 `60%` | 4 枚，每枚 `50%` |
| 炽燃地面 | 半径 `0.75`，持续 `2秒`，每 0.5 秒 `25` 火伤 | `0.9 / 3秒 / 35` | `1.05 / 4秒 / 45` |
| 冰寒减速 | `+15%` 水伤，减速 `15%/1秒` | `+25%`，`25%/1.5秒` | `+35%`，`35%/2秒` |
| 连锁闪电 | 延迟 `0.7秒`，半径 `0.65`，`70` 电伤 | `0.8 / 110` | `0.95 / 160` |
| 混沌腐蚀 | 每秒 `20` 混沌伤，持续 `2秒` | `30/3秒` | `45/4秒` |
| 闪现突袭 | 冷却 `8秒`，预警 `0.7秒`，下次伤害 `+20%` | `6秒/0.6秒/+35%` | `4秒/0.5秒/+50%` |
| 死亡爆破 | 延迟 `1.1秒`，半径 `0.9`，`120` 物伤 | `0.9秒/1.15/190` | `0.75秒/1.4/280` |

具体规则：

- 强壮的抗击退同时作用于普通击退和上挑水平冲量，不取消上挑或浮空状态。
- 狂暴缩放攻击前摇、后摇和冷却，但不得产生 0 tick 阶段。
- 迅捷缩放移动和技能冷却，不改变攻击有效帧。
- 坚甲使用 Stage 8 已确认的护甲曲线，只减免物理生命伤害，不减破韧伤害或元素伤害。
- 护盾在连续无受击达到等级延迟后一次恢复至最大值；再次受击会重置恢复计时。
- 多重投射的伤害比例逐弹应用，所有弹体共享一次攻击序号。
- 多重投射使用新增的 `projectile_capable` 能力标签，不把仅生成地面区域的 `chaos_hazard` 误判为弹体怪。
- 冰寒减速、连锁闪电和混沌腐蚀要求既有 `direct_target` 标签，不能抽给只执行支援行为的 `water_support`。
- 炽燃地面 M1/M2/M3 每 `180/150/120` tick 生成一次，每 30 tick 结算一次火伤；怪物死亡时清除其所有非死亡效果区域。
- 冰寒减速只刷新持续时间，使用最高强度，不进行乘算叠层。
- 连锁闪电只生成一次二段落点，不递归触发自身。
- 混沌腐蚀只刷新，不叠层；已经生效的持续伤害不可闪避。
- 闪现突袭必须先完成预警；若目标位置不合法则钳制到房间边界内的最近合法点。
- 死亡爆破属于死亡触发对象，允许原怪物销毁后继续完成预警和爆炸。

## 8. 生命周期、固定池与安全降级

怪物生成时一次性应用最大生命、最大破韧、移动、护盾等静态投影；伤害、攻速、冷却和触发行为从运行时词缀集合求值。词缀产生的投射物与区域继续复用现有固定池：96 个怪物、384 个投射物、96 个区域。

- 怪物死亡时清除所有以它为 owner 且 `persists_after_owner_death == false` 的投射物和区域。
- 死亡爆破区域设置死亡后存续标记；不能再触发其他死亡效果。
- 固定池容量不足时不得覆盖既有对象。本次触发安全取消，增加对应诊断计数，并且不得消费会让表现与规则失配的预警状态。
- 所有时间以 60 Hz 固定 tick 表示；浮点秒数在目录构建时转换并验证不为零。
- 所有伤害乘法使用 checked 或饱和中间值；非法目录、溢出或无法满足目标词缀数进入显式 fault/diagnostic 路径。

## 9. 经验与直接掉落

危险基础分和等级倍率：

```text
低危 / 中危 / 高危 = 1 / 2 / 3
M1 / M2 / M3       = x1 / x2 / x3
monster_score       = 所有词缀危险基础分 * 各自等级倍率之和
```

多词缀危险分直接相加，不封顶。`defeated` 战斗事件携带本只怪物的危险分、稳定出生序号、位置和怪物 ID，地下城会话不从已销毁运行时反查奖励数据。

结算规则：

```text
drop_chance_bp = min(5000, 100 + monster_score * 150)
xp_multiplier  = 100% + monster_score * 10%
item_level     = min(100, depth + min(10, ceil(monster_score / 3)))
```

- 无词缀怪保持现有 1% 掉落率和基础经验。
- 每只怪物最多直接掉 1 件装备，继续使用 `wave_index * 96 + spawn_index` 的 0～191 稳定掉落序号。
- 部位、稀有度和装备词缀继续使用 Stage 8 生成器；提高后的有效物品等级自然改变稀有度与装备词缀阶级权重。
- 词缀、掉落机会、掉落部位、物品内容和物品 ID 使用独立随机域。
- 领取位图、committed/not_committed/indeterminate 事务和重载防复制语义保持不变。
- 额外经验使用饱和整数运算，不设置玩法奖励上限。

## 10. 视觉、声音与快照

每个怪物快照暴露最多 3 个词缀 ID、等级和只读预警状态：

- 血条旁显示词缀简称和 M 等级。
- 基础强化使用灰白，防御使用蓝，火焰使用橙红，水系使用青蓝，闪电使用黄，混沌使用紫。
- 高危词缀增加红色脉冲边框。
- 闪现突袭、连锁闪电和死亡爆破使用独立地面/角色预警图形和声音。
- 同类提示音设置短冷却并限制同帧播放数量，避免多怪同时触发造成爆音；声音限制不得改变战斗规则。
- raylib 层只能按快照绘制和播放，不得重新计算范围、命中或触发时间。

## 11. 存档与兼容

词缀集合完全由当前房间种子、深度、波次和出生序号推导，不加入稳定检查点：

- V1～V4 旧存档无需格式迁移。
- 重载当前房间时，相同怪物得到相同词缀和等级。
- 已领取掉落仍由现有 192 位领取位图阻止重复获得。
- 瞬时词缀计时器、投射物和区域不写入存档，遵循现有当前房间战斗重建语义。
- 新词缀随机域不得改变旧存档生成的房间、生态、洞、深渊标记、怪物类型或位置。

## 12. 验证

### 12.1 自动化

必须新增并通过：

1. 12 个稳定 ID、名称、危险级、标签、M1～M3 数值和目录完整性 golden 测试。
2. 相同种子/深度/出生序号字节等价，不同随机域互不干扰，单怪词缀不重复。
3. 深度边界 `3/4/9/10/19/20/39/40` 的数量与等级权重测试。
4. 远程多重投射、近战闪现突袭的适用性过滤和候选不足显式失败测试。
5. 12 个词缀分别验证 M1～M3 数值、行为、预警和反制窗口。
6. 强壮不取消上挑浮空，坚甲不减破韧，减速/腐蚀刷新不叠层，连锁闪电不递归。
7. 三高危组合生成和运行测试，不添加房间或单怪高危上限。
8. owner 死亡清理、死亡爆破存续、投射物/区域容量耗尽安全降级测试。
9. 危险分、额外经验、直接掉落基点、有效物品等级和 100 级封顶测试。
10. 普通怪仍为 1% 掉落，0～191 序号、领取位图和重载防复制保持测试。
11. raylib 纯视图测试覆盖简称、M 等级、分类颜色、高危脉冲和三种独立预警。
12. 96 怪、384 投射物、96 区域压力测试，验证无越界、无覆盖且战斗热路径无动态分配。
13. 固定根种子运行两个独立 session 至少 1,000 房，逐项比较房间、怪物、词缀、击杀奖励和装备结果。

Debug 与 Release 必须完整构建并通过全部 CTest；`git diff --check` 必须干净。

### 12.2 窗口验收

1. 启动 raylib 游戏，在浅层观察少量 M1 词缀及血条旁完整标识。
2. 使用确定性调试入口进入高深度房间，观察 2～3 词缀和 M2/M3 组合。
3. 分别观察多重投射、炽燃地面、连锁闪电、闪现突袭和死亡爆破的图形与声音预警。
4. 使用 L 上挑强壮怪，确认浮空仍存在，仅水平击退减弱。
5. 击杀带词缀怪，确认装备直接出现在死亡位置，危险分更高时奖励统计符合规则。
6. 重启并重进相同房间，确认怪物词缀与未领取掉落内容确定一致，已领取掉落不复制。
7. 制造多怪极端组合和固定池压力，确认游戏不崩溃且诊断计数可见。

## 13. 完成边界

完成全部自动化、窗口验收与代码审查后，停止在独立 `codex/stage9-monster-affixes` 工作树。不得开始后续怪物词缀扩展、深渊专属词缀、正式深渊系统或 Stage 10 内容，等待用户验收。
