# 全局输入延迟与上挑表现修复设计

## 1. 目标

降低移动、跳跃、轻攻击、上挑等全部操作的输入到画面响应延迟，并让 L 上挑的动作与怪物浮空清晰可见。L 的前摇、伤害、破韧和攻击范围保持不变。

## 2. 根因与处理

- 当前固定步渲染通过 `previous -> current` 插值，玩家和即时反馈天然显示较旧状态。玩家改为直接绘制最新逻辑快照；怪物和非即时环境仍可插值。
- raylib 同时启用 VSync 和 `SetTargetFPS(60)`。保留 VSync，移除软件限帧，避免重复等待。
- 连续移动输入继续每帧采样；按键边沿先写入持久输入缓存，即使当前显示帧没有产生固定逻辑步，也不得丢失。
- 每个显示帧先采样输入，再推进固定逻辑步；下一逻辑 tick 必须能消费新输入。

## 3. 上挑表现

- 不调整 launcher 的 7/4/17 帧数据。
- 玩家进入 launcher 时绘制明确的向上挥击姿势和上升弧光，前摇阶段也立即显示动作启动。
- 命中后怪物继续在最高点悬停 30 个有效 tick，再恢复下落。
- 名字和血条跟随怪物投影位置，避免遮住浮空距离。

## 4. 约束

- 逻辑固定步仍为 60 Hz，确定性和存档行为不变。
- Combat Core 不依赖 raylib，不增加热路径动态分配。
- 不改变怪物护甲、伤害、破韧、房间规则或键位。

## 5. 验收

1. 输入边沿在零逻辑步显示帧后仍会在下一 tick 被消费。
2. 玩家移动和动作绘制使用最新快照，不再落后一帧。
3. raylib host 不再同时启用 VSync 与 `SetTargetFPS(60)`。
4. L 按下后当帧可见动作启动，命中后怪物有清晰击飞与 0.5 秒悬浮。
5. Debug 构建与全量 CTest 通过，启动游戏进行实际操作验收。
