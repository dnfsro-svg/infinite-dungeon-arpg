# 怪物大幅削弱与生命药掉落设计

## 目标

降低新角色在普通房间中的瞬间死亡概率，同时保留大房间、多怪物、随机生态和后期词条成长。加入无需背包操作的生命药掉落，让玩家在持续战斗中通过击杀恢复生命。

本设计采用用户确认的极度削弱方案：怪物基础生命约保留 45%，基础伤害约保留 30%；仅第 1–3 层禁止怪物词条；怪物数量、移动速度、攻击动作、房间密度和第 4 层后的既有成长不降低。

## 怪物基础数值

`monster_catalog.cpp` 中八种怪物使用以下冻结值：

| 怪物 | 原生命 | 新生命 | 原伤害 | 新伤害 |
|---|---:|---:|---:|---:|
| 火焰炸弹 | 220 | 100 | 120 | 36 |
| 火焰冲锋 | 420 | 190 | 90 | 27 |
| 水之盾卫 | 700 | 315 | 70 | 21 |
| 水之辅助 | 300 | 135 | 0 | 0 |
| 雷电射手 | 240 | 110 | 40 | 12 |
| 雷电突进 | 280 | 125 | 60 | 18 |
| 混沌追击 | 260 | 120 | 45 | 14 |
| 混沌地面 | 320 | 145 | 35 | 11 |

最大破韧、护盾、移动速度、预警、攻击有效帧、恢复帧、冷却和投射物速度保持不变。怪物词条和深渊规则继续在新基础值之上计算，因此后期仍能形成生命、伤害和速度乘区。

## 前三层词条保护

普通词条深度表的第一个区间改为第 1–3 层固定：

```text
词条数量权重 = 100 / 0 / 0 / 0
词条等级权重 = 100 / 0 / 0
```

第 4 层起完全恢复当前规则：第 4–9、10–19、20–39、40+ 层的数量和等级权重不变。

深渊词条补充也必须遵守同一保护：深度不超过 3 时直接保留空词条，不强制补入深渊词条。深渊的怪物预算、环境危害、奖励和房间身份不变；深渊环境按最大生命百分比造成的伤害也不在本次修改范围内。

## 生命药规则

- 每个有奖励资格的怪物死亡后先判定强化券；未掉落强化券时，再独立进行确定性生命药判定，概率固定为 `3000 bp`，即 30%。
- 普通材料掉落与生命药互不排斥。
- 强化券使用每只怪物的次级掉落位并具有优先权，因此生命药的最终实际掉落率不会高于 30%。
- 每瓶固定恢复实际最大生命的 `2500 bp`，即 25%，向上取整；生命药不受深渊 `player_resource_restore_bp` 折减。
- 生命恢复封顶为最大生命。玩家生命为零或死亡快照已建立时，生命药不能生效或复活玩家。
- 是否自动使用采用整数比例比较；当前生命小于或等于最大生命的 75% 时符合条件，恰好 75% 也使用。

## 自动领取行为

怪物掉出生命药后：

1. 若玩家存活且生命不高于 75%，药物立即进入领取事务，不检查玩家与掉落点距离。
2. 若玩家生命高于 75%，药瓶保留在当前房间地面。
3. 之后任意固定帧检测到生命不高于 75% 时，按稳定掉落序号从小到大依次领取房间内药瓶。
4. 每次领取成功后重新计算比例；生命重新高于 75% 时停止，避免无意义消耗。
5. 离开房间时仍未使用的药瓶消失，不进入背包、不累计数量、不跨房间保存。

“直接领取”表示不需要靠近或按键，但回血只在对应原子事务确认成功后出现。若已有保存事务正在处理，药瓶保持在地面并在下一个可提交时机继续排队。

## 数据边界与事务

生命药不是 `MaterialId`，不能扩大 `kMaterialCount`，否则会改变 V8 存档中固定长度的材料数组。新增独立的固定容量地面生命药结构和快照；容量固定为 `kGroundDropCapacity = 192`，每只怪物最多对应一瓶，运行时不分配内存。

生命药复用每只怪物的次级材料领取位：

```text
common material ordinal = spawn_ordinal * 2
coupon or potion ordinal = spawn_ordinal * 2 + 1
```

强化券和生命药互斥，因此现有 `material_claimed_drop_bits` 足以记录已领取状态，不增加存档字段、不升级 codec。生命药使用独立随机域，不能改变普通物品、材料、强化券、房间和出口的既有随机序列。

新增独立的 `GroundHealthPotion`/`GroundHealthPotionSnapshot`，避免用无效材料 ID 冒充药物。领取请求接入现有异步双槽保存管线：

- 提交成功：设置领取位、移除药瓶、调用战斗层的百分比生命恢复接口，并发布回执。回血是已确认提交之后的运行时副作用，当前生命本身不写入存档。
- 提交失败或结果不确定：不回血、不移除药瓶、不发布成功提示。
- 重试时使用同一稳定序号和随机结果，不能重复回血。

若进程恰好在领取位写入成功后、运行时回血前退出，重载时不得再次领取同一药瓶；战斗生命按现有房间重建规则恢复，不为此扩展 V8 存档。测试必须冻结这一崩溃窗口语义。

最后一只怪死亡时，清房准备可能早于下一次自动领取。若此时生命不高于 75%，符合条件的药瓶领取位必须并入清房事务，清房提交成功后再恢复生命；生命高于 75% 的药瓶可留在已清理房间，离开后消失。

## 战斗层接口

战斗层新增以最大生命比例恢复的窄接口，负责：

- 校验玩家仍存活且最大生命有效；
- 使用 64 位中间值计算 25% 并向上取整；
- 绕过 `player_resource_restore_bp`，确保普通房和深渊房都固定恢复 25%；
- 封顶最大生命；
- 返回实际恢复量，供 HUD 提示使用。

地下城层只决定掉落、领取顺序和事务所有权，不直接改写玩家运行时生命。渲染层只消费地面药物快照与领取回执，不参与掉落或回血判断。

## 视觉与反馈

在现有物品材质图集中使用未占用单元新增独立高清生命药图标：纯红玻璃药瓶、金属瓶盖、清晰轮廓，不在图片中烘焙文字。地面表现使用红色光柱和高对比标签“生命药”。

领取成功后 HUD 显示“生命药 +N HP”，`N` 为实际恢复量。高于 75% 留在地面的药瓶持续可见；事务失败不播放成功反馈。文字继续使用已打包的高分辨率纯色 CJK 字体路径。

## 错误处理

- 地面药瓶池饱和时记录诊断计数，不能覆盖现有药瓶或进入故障循环。
- 无效序号、重复领取、已死亡玩家、无战斗实例或不允许领取的房间阶段均拒绝请求。
- 保存失败保持领取前状态；提交回执与待处理序号不一致时沿用现有存档回执故障处理。
- 生命计算不得溢出、产生负数或超过最大生命。

## 验证

严格按 TDD 实施，每项生产行为先由失败测试定义：

- 战斗测试冻结八种怪物的新生命和伤害值。
- 词条测试验证第 1–3 层必为空，第 4 层恢复现有权重；深渊前三层也不补词条。
- 掉落测试验证独立随机域、30% 概率、普通材料可共存、强化券优先和重载确定性。
- 生命测试验证 25% 向上取整、深渊房仍固定 25%、最大生命封顶、死亡不复活和实际恢复量。
- 地下城事务测试验证 75% 临界值、全房间自动领取、多瓶按序使用、192 容量、保存失败回滚、提交后退出防重、最后击杀与清房提交。
- 平台测试验证专用药瓶图标、红色高对比地面标签和“生命药 +N HP”提示。
- 固定容量压力测试验证战斗和拾取热路径零动态分配。
- 更新因前三层词条规则而有意改变的固定种子黄金轨迹，并保留其他随机域不变证明。
- 完整运行 Debug/Release 构建、全部 CTest，以及使用全新隔离存档从第 1 层试玩到第 3 层。

## 验收标准

- 新角色面对第一层普通怪物时，怪物快照展示冻结后的生命和伤害基础值。
- 第 1–3 层任何普通或深渊怪物均无词条；第 4 层重新出现原有词条概率。
- 生命不高于 75% 时，掉落生命药无需移动或按键即可在事务成功后回血。
- 生命高于 75% 时药瓶不会被消耗；降到阈值后同房间药瓶自动使用。
- 生命药不会挤占普通材料或装备掉落，不改变强化券内容，不修改存档版本。
- 全套自动测试通过，并留下第 1–3 层实际试玩记录。

## 非目标

本次不降低怪物数量、移动速度、攻击动作、房间尺寸或房间密度；不调整玩家伤害、防御装备、深渊环境百分比伤害、现有材料与强化系统；不增加药水背包、快捷键、药水等级、持续恢复、冷却或跨房间保存。
