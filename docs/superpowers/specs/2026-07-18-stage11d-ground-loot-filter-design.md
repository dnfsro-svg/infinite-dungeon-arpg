# Stage 11-D 地面装备标签、过滤与拾取反馈设计

日期：2026-07-18  
分支：`codex/stage11d-loot-filter`  
基线：已验收 Stage 11-C `d6bdbd0d6e8f795fed096737ac89ea4e070f7d8e`

## 1. 目标

Stage 11-D 让玩家在不打开背包的情况下识别地面装备，并用一个简单、持久化的过滤预设阻止低价值装备继续进入无限背包。现有靠近自动拾取手感保留；过滤结果同时控制地面表现和自动拾取资格，避免“标签被隐藏但物品仍被捡走”的伪过滤。

本阶段只改变装备的表现与自动拾取选择，不改变物品生成、掉率、词缀、装备数值、三合一、战斗、地下城随机流或角色 V6 存档。

## 2. 已选方案

采用三个有序预设：

1. `显示全部`：普通、魔法和稀有装备均显示并自动拾取；这是默认值和旧设置迁移结果。
2. `魔法以上`：只显示并自动拾取魔法、稀有装备。
3. `仅稀有`：只显示并自动拾取稀有装备。

该方案优于仅隐藏标签，因为后者仍会让低价值装备进入背包；也优于首版直接实现自定义规则语言，因为当前只有三种稀有度、六个固定基底，自定义脚本与编辑器没有足够收益。

深渊宝箱奖励不受预设限制：始终显示、始终自动拾取，并继续参与既有离房放弃确认。过滤只作用于普通怪物掉落，不能让关键奖励静默消失。

## 3. 玩家可见行为

### 3.1 地面标签

- 通过过滤的地面装备同时显示既有部位图标和标签。
- 标签正文为 `稀有度 基底名称 · i物品等级`，例如 `稀有 胸甲 · i24`。
- 普通、魔法、稀有沿用白、蓝、金三种颜色；深渊奖励额外使用紫色边缘标记。
- 标签锚定地面投影位置上方，使用固定容量布局；重叠时按屏幕纵向稳定错开，不随帧顺序抖动。
- 标签必须留在屏幕安全区内；192 个地面槽位达到上限时仍不得堆分配或越界。
- 被过滤的普通怪物掉落不绘制图标、阴影或标签，但生产地面物品仍存在；玩家把预设调回更宽松档后会立即重新看到并可拾取。

### 3.2 自动拾取

- Dungeon 每个固定步显式接收当前自动拾取策略；默认参数等价于 `显示全部`，保持现有测试和旧调用语义。
- 玩家进入拾取半径时，Dungeon 按原有地面槽序扫描，跳过不符合预设的普通怪物掉落。
- 深渊奖励永远符合自动拾取条件。
- 过滤不影响显式 `request_pickup(ordinal)` 的合法性；该接口继续只验证距离、来源和事务状态，供验证器和未来交互方式复用。
- 同一固定步仍保持“符合过滤的自动拾取先于出口请求”，现有原子保存和离房确认语义不变。

### 3.3 拾取反馈

- `DungeonRuntime` 在同步提交拾取保存前，从生产 pending ordinal 和生产地面快照缓存该装备的固定容量回执候选。
- 只有保存提交成功、Session 接受回执且该地面槽消失后，runtime 才发布带 commit generation 的只读拾取回执；正式 host 不依赖不可呈现的中间 pending snapshot。
- HUD 观察到新的已提交回执后，在情境区显示一次 `已拾取：稀有 胸甲 · i24`，并沿用现有短通知寿命。
- 保存失败、事务回滚或地面槽仍存在时不得显示成功反馈。
- 深渊奖励反馈使用深渊配色，但不改变奖励状态机。
- 回执和反馈只属于平台运行/表现状态，不进入角色存档、设置文件或确定性哈希。

## 4. 设置与迁移

### 4.1 设置模型

在 `SettingsData` 增加 `LootFilterMode`：`show_all`、`magic_or_better`、`rare_only`。默认值为 `show_all`，校验拒绝枚举范围外的值。

暂停设置页在 VSync 后增加一行 `Loot Filter`，左右键或确认键循环三个预设。它属于设置草稿：

- 修改草稿时只预览地面标签，不改变当前固定步自动拾取策略；
- 选择“应用”并成功持久化后，已提交预设才控制自动拾取；
- 取消恢复进入设置页之前的已提交表现；
- “恢复默认”把预设恢复为 `显示全部`。

这样可避免玩家浏览设置时因临时选择导致地面装备被不可逆拾取。

### 4.2 设置文件 V2

- 设置文件总长度继续为 44 字节，沿用双槽、revision 和 CRC。
- 编码格式号从 1 升为 2，原保留字节 23 存放 `LootFilterMode`。
- 解码器同时接受格式 1 和格式 2；格式 1 要求旧保留字节仍为零，并迁移为 `show_all`。
- 下一次设置应用会按格式 2 写入新槽；不主动重写仅加载的旧槽。
- 双槽选择继续只按合法性与 revision 决定，V1/V2 可混合存在。

角色 V6 存档完全不变。

## 5. 架构与数据流

### 5.1 无平台依赖的过滤规则

`dungeon` 定义只包含物品稀有度与来源判断的 `AutoPickupPolicy`，不得依赖 `platform/settings` 或 raylib。`DungeonSession::tick` 接收策略，`request_nearby_pickups` 使用同一策略；无参数默认值保持 `show_all`。

生产数据流为：

`已提交 SettingsData` → host 映射为 `AutoPickupPolicy` → `DungeonRuntime::fixed_tick` → `DungeonSession::tick` → 过滤后的自动拾取事务。

设置草稿只传给标签 ViewModel 做预览，不进入固定步。

### 5.2 快照与标签 ViewModel

`GroundItemSnapshot` 增加构建标签所需的 `base_id` 与 `item_level`，仍只复制现有生产物品字段。新增无状态、固定容量的 `ground_loot_view.hpp/.cpp`：

- 输入 `DungeonSnapshot`、当前预览过滤模式、屏幕尺寸；
- 输出最多 `kGroundDropCapacity` 个标签条目；
- 每个条目包含 ordinal、投影锚点、矩形、颜色角色和 NUL 终止固定字符数组；
- 只读 item catalog，不调用 Session、Store、随机数、输入采样或固定 tick；
- 构建与布局热路径不得分配。

`room_renderer` 只绘制该 ViewModel，不再自行决定过滤规则或格式化物品文本。

### 5.3 拾取提交回执与反馈状态

正式 runtime 的 `fixed_tick()` 会同步执行 `service_pending_save()`，所以 pending snapshot 不会稳定出现在 presented frame。不得通过测试私有注入假设 HUD 一定能看到 pending 阶段。

`DungeonRenderStatus` 增加固定字段 `LootPickupReceipt`：commit generation、item ID、base ID、item level、rarity、source 和有效标记。runtime 只在真实 `loot_pickup`/`abyss_reward_claim` 保存提交成功并被 Session 接受后更新回执；失败、回滚、其他保存类型或 fault 不更新。

新增固定容量 `LootPickupFeedbackState`，观察相邻 `DungeonRenderStatus`：

- 只在回执 commit generation 或 item ID 相对上次观察发生合法前进时格式化一次反馈；
- 首次附着到已有旧回执时只建立基线，不重放历史拾取；
- 回执倒退、非法字段、恢复界面、fault 或保存错误清除基线且不发布成功；
- 同一个 commit generation + item ID 最多发布一次。

HUD 通知层消费该一次性固定缓冲事件，不读取背包、不调用 Session，也不改变生产状态。

## 6. 异常与边界

- 非法过滤枚举：设置校验失败，运行时映射回 `show_all` 并增加仅 F1 可见的受控诊断，不静默采用更严格模式。
- 快照中的 base ID 非法：该物品仍按稀有度决定拾取；标签使用 `未知装备`，不得崩溃或访问越界。
- 标签格式截断：固定缓冲区始终 NUL 终止，长文本使用短格式，不分配临时字符串。
- 192 个活跃地面物品：布局按 ordinal 稳定，超出可见安全区的条目夹紧并继续绘制，不改变地面物品顺序。
- 设置保存失败：自动拾取继续使用旧提交模式，预览恢复旧模式，并显示既有设置错误。
- 角色死亡、恢复、暂停：固定步本来已冻结，过滤器不得引入额外拾取路径。

## 7. 测试与正式证据

### 7.1 单元和压力测试

- Settings：三个合法模式、非法模式、默认值、草稿预览/应用/取消/恢复默认。
- Codec/Store：V1 到内存迁移、V2 往返、V1/V2 混合双槽、CRC/保留位/非法模式、1000 次保存重启。
- Dungeon：三档怪物掉落资格、深渊绕过、同半径多物品稳定顺序、过滤拾取先于出口、显式拾取不受过滤影响。
- Snapshot：base ID、物品等级、来源、ordinal 与生产地面物品一致。
- 标签：三档可见性、深渊常显、中文摘要、稀有度颜色、重叠消解、三档分辨率安全区、非法 base、NUL 终止。
- 回执/反馈：同步真实保存成功只发一次；首次附着旧回执、保存失败、回滚、其他保存、非法/倒退回执和 fault 不发。
- 分配：10 万次过滤判断、标签构建/布局与未变化反馈刷新零堆分配。

### 7.2 架构守卫

- Dungeon 不得依赖 settings 或 raylib；settings 不得依赖 dungeon。
- 标签 ViewModel 不得调用 Session、Store、随机数、输入函数或 `TextFormat`。
- `room_renderer` 不得直接读取 `SettingsStore` 或决定自动拾取资格。
- 守卫自测必须能拒绝动态字符串、快照私有注入、过滤后仍自动拾取普通低稀有度，以及深渊奖励被过滤。

### 7.3 正式 raylib 场景

通过生产 host、生产快照和后 `EndDrawing()` 截图路径生成 fresh 1280×720 证据：

1. `显示全部`：同屏普通、魔法、稀有标签；
2. `魔法以上`：普通物品仍在生产快照但完全不绘制，魔法与稀有可见；
3. `仅稀有`：只有稀有普通掉落可见；
4. `仅稀有 + 深渊`：低稀有度深渊奖励仍可见；
5. 设置草稿预览、取消后恢复；
6. 自动拾取成功 HUD 反馈。

验证器检查截图新鲜度、哈希、尺寸、关键区域、过滤前后生产 item ID 一致、被过滤物品未进入背包、深渊奖励可领取，以及所有场景使用正式 host 和真实保存事务。

- 物品生成、掉率、装备平衡、战斗、地下城规则或角色 V6 存档改动；
