# Stage 6 通用 Modifier 与 Effect 系统设计

## 1. 目标与范围

Stage 6 建立装备、星盘和怪物词条未来共用的属性修正与限时效果核心，同时迁移两个现有机制作为真实调用方：水系支援怪的限时护盾，以及轻型怪受到的 1.25 倍击退与浮空冲量。

本阶段不实现装备、掉落、星盘节点、怪物随机词条、玩家构筑 UI、永久效果存档或 Stage 7 内容。

## 2. 模块边界

新增独立 `modifiers` 静态库。该库只依赖标准库和项目 `core` 的固定容量容器，不依赖 combat、dungeon、progression、persistence 或 raylib。

模块分为三个职责：

- `modifier_math`：纯属性求值、条件判断和转换。
- `effect_set`：固定容量 Effect 的施加、刷新、层数、计时和移除。
- `effect_triggers`：把 Effect 生命周期和战斗信号转换为有界命令，不直接递归修改调用方状态。

combat 负责把自身实体、标签和事件翻译成模块输入，并消费模块输出。

## 3. 数值表示与求值顺序

通用数值使用有符号 64 位定点整数，比例为 `10000 = 100%`。百分比修正使用基点整数，所有乘法使用 64 位中间值、明确舍入和饱和处理。

固定求值顺序：

1. 读取基础值。
2. 累加所有固定值修正。
3. 汇总所有 `increased/reduced`，只乘一次。
4. 按稳定 ID 顺序依次应用 `more/less`。
5. 处理从来源属性到目标属性的转换。
6. 对最终值执行该属性定义的上下限钳制。

同一阶段不得依赖容器插入顺序。相同稳定 ID 的活动 Modifier 非法并被拒绝。

## 4. Modifier 数据

每条 Modifier 包含：

- 稳定 `ModifierId`。
- `StatId` 目标属性。
- 操作类型：`flat`、`increased`、`more`、`conversion`。
- 有符号数值。
- 来源稳定 ID。
- 必需标签、禁止标签和条件掩码。
- 稳定优先级。

调用方提供 `ModifierContext`，包括攻击、防御、移动、冲量、轻型、重型、近战、投射物、护盾等标签，以及命中、受击、破韧、低生命等条件位。

条件不满足的 Modifier 不参与求值。空列表必须严格返回基础值。

## 5. 转换规则

转换从一个 `StatId` 的已修正值抽取比例并写入另一个 `StatId`。同一来源属性的总转换比例最多 100%。超过 100% 的部分按优先级、稳定 ID 顺序截断。

一次求值只处理一层转换：转换后的目标值不得在同一次求值中再次作为转换来源，避免循环与双重收益。负转换和目标等于来源均非法。

## 6. Effect 数据与生命周期

每个实体使用固定容量 `EffectSet`，初始容量为 8。每个 Effect 包含：

- 稳定 `EffectId` 和来源句柄。
- 剩余持续 tick。
- 当前层数与最大层数。
- 刷新规则：拒绝、刷新持续时间、增加层数、替换较弱值。
- 固定数量 Modifier。
- 固定数量 Trigger。

施加、刷新、到期和移除都由确定性 tick 驱动。Effect 遍历期间不直接增删集合；操作先写入固定容量命令队列，再在安全边界统一提交。

容量满或命令队列满时拒绝新操作、增加诊断计数，不覆盖已有 Effect，不分配堆内存。

## 7. Trigger

支持 Stage 6 所需触发信号：`on_apply`、`on_refresh`、`on_expire`、`on_hit`、`on_hurt`。

Trigger 只生成数据命令，例如增加护盾、移除护盾、施加 Effect、移除 Effect 或发送反馈事件。禁止触发器直接调用另一个触发器，防止递归和无限循环。每个逻辑 tick 的命令数量有固定上限。

## 8. 现有机制迁移

### 水系支援怪护盾

支援怪现有的护盾量和持续时间保持不变。支援技能改为施加 `water_barrier` Effect：

- `on_apply/on_refresh` 设置目标护盾为现有最大护盾值。
- Effect 持续 tick 取现有数据。
- `on_expire` 清除仍由该 Effect 提供的护盾。
- 护盾被伤害耗尽时立即移除 Effect，防止后续错误刷新。

现有快照中的 shield 字段继续保留供渲染和测试使用，但其生命周期由 Effect 驱动。

### 轻型怪冲量

移除 `impulse_scale()` 中直接返回 1.25 的硬编码。基础冲量比例为 10000；轻型上下文应用稳定 Modifier `light_target_impulse_more = 12500`。普通和重型上下文保持 10000。

水平击退和垂直浮空共用同一次求值结果，原有战斗数值和轨迹必须保持。

## 9. 可观测性与存档

CombatSnapshot 增加每个怪物的活动 Effect 数量和 Effect 溢出诊断。Debug HUD 可显示选中目标的 Effect 数量。

房间内 Effect 属于瞬时战斗状态，不写入永久存档。房间重置、销毁或进入下一房间时全部清除。

## 10. 测试与验收

1. 固定值、提高、更多/更少、条件和钳制顺序精确。
2. 不同插入顺序得到相同结果；重复稳定 ID 被拒绝。
3. 转换总量钳制到 100%，无循环、无双重转换。
4. Effect 施加、拒绝、刷新、叠层、替换、到期和移除边界精确。
5. Trigger 命令顺序确定，禁止递归，容量溢出安全计数。
6. 水系支援护盾量、持续时间、耗尽清除和刷新行为与迁移前一致。
7. 轻型、普通、重型目标的水平与垂直冲量回归数值不变。
8. 36,000 tick 确定性、1000 房间压力测试、零热路径分配和架构边界通过。
9. Debug 与 Release 全量 CTest 通过。

## 11. 停止条件

完成自动测试和当前机制可视回归后，停止在独立 Stage 6 工作分支。不得开始 64 节点星盘、装备、掉落或随机词条，等待用户确认。
