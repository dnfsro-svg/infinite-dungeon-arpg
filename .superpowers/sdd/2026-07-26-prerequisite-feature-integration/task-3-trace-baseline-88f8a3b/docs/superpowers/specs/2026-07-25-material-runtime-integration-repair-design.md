# 材质运行时完整接入修复设计

## 目标

修复“材质文件已经打包和部署，但正式游戏仍显示几何占位、错误切片或程序面板”的运行时集成问题。范围覆盖异生态怪物、火系怪物现有姿势、四元素出口门、两个主动技能、水/雷/混沌环境物件、死亡面板、动态战斗文字和小键盘技能输入。

本批不改变伤害、AI、碰撞、掉落、房间生成、技能石装卸或存档语义。攻击预警线、危险区边界等承担精确判定提示的程序图形继续保留。

## 已确认现状

- Stage 12 源码、Release 构建和安装目录中的 52 个文件逐文件一致，问题不在部署。
- `MaterialPack` 只保留公共图集和当前房间生态图集；遭遇生成允许异生态怪物，因此异生态怪物必然缺少图集并退回几何轮廓。
- 火焰爆弹兵和冲锋兵被排除在多帧 presenter 之外，只使用七张状态图；两张火怪图集中仍有约十张已制作姿势未接入。
- 四扇出口门全部按当前房间生态选择同一张门图。关闭态又用高不透明红色矩形覆盖门主体，默认 raylib 字体无法显示 Unicode 箭头，最终出现红框和问号。
- 拔刀斩的 36 张图只在命中附近显示约四张；暴风式的 24 张图只使用其中十九张。两招通过独立 `DrawTexturePro` 路径叠在基础玩家动画上，没有颜色图与材质图配对，也没有进入统一材质着色管线。
- 水、雷、混沌环境图是场景拼贴图，现有 manifest 将其按固定 256 像素方格硬切，导致门和物件边缘截断、锚点错误，并在最低窗口尺寸出现越界。
- 死亡面板没有使用现成的 `ui_warning_modal` 和 `ui_label_plate`。
- 玩家基础动作、普通攻击、跳跃、上挑、四生态背景、主要掉落/UI、深渊洞口和 Stage 12 元素特效已经正确接入。

## 方案选择

采用动态选择性常驻方案。禁止一次加载全部图集，因为现有全包已经约 302 MB，加入技能材质后会超过 256 MB 目标。也不采用逐对象即时加载，因为它会把磁盘与纹理创建带回绘制热路径并造成卡顿。

运行时根据不可变快照生成固定容量的 `MaterialResidencyRequest`：

- 始终请求公共玩家、UI、物品和基础特效图集。
- 请求当前房间的背景与环境图集。
- 请求当前战斗快照中所有存活或待绘制怪物对应的图集，不受房间生态限制。
- 请求五个技能槽中已装备主动技能的图集；未装备技能不常驻。
- 四元素门使用一个紧凑公共门图集，不需要同时常驻四套环境拼贴图。

`MaterialPack` 只在请求集合发生变化时同步差异：先校验预算并加载新增图集，成功后再释放不再需要的图集。单个图集失败只让对应对象回退，并记录一次包含资源 ID 和路径的警告；不得使其他已加载材质一起失效。

## 怪物材质

异生态怪物按怪物 ID 请求其真实图集。健康资源下，水、雷、混沌六种怪物必须走完整动画帧，火系两种怪物必须至少走显式关键姿势序列，不得落入几何轮廓。

火焰爆弹兵现有规则网格中的五张额外姿势接入特殊攻击、恢复和投弹阶段。火焰冲锋兵的附加姿势使用显式源矩形，不能继续套用硬编码的 96 像素、九列取帧器。火怪帧定义统一携带图集、源矩形、脚底锚点和持续时间。

本批只承诺完整使用现有原创火怪姿势，不把重复帧或插值帧伪装为完整的 12/16/20/8/16 帧动作板。缺失的高帧率火怪中间帧仍属于后续资产生产，不得在本批验收中虚报完成。

## 四元素门

建立紧凑的公共高清门颜色图与材质图。四个 256 像素单元分别为火、水、雷、混沌门，来源于现有原创高分辨率生态资源，并重新导出为带透明留白的独立物件；禁止直接保留拼贴图硬切边缘。

门根据 `door_theme(direction).element` 选择材质，而不是根据当前房间生态。关闭态保留门体细节，只降低亮度并显示小型锁定标记；禁止整块红色覆盖。开放态恢复正常亮度并允许轻微元素边缘光。方向提示使用按屏幕比例绘制的矢量箭头，标签继续使用高分辨率 HUD 字体，从根源上消除缺字问号。

## 两个主动技能

两张现有技能颜色图保持原创内容不变，新增同尺寸材质图。材质图由确定性离线脚本根据透明度、暗钢/古金区域和蓝白能量亮度生成粗糙度、金属度与发光通道；运行时不生成或解析图片。

- 拔刀斩：90 tick 时间线完整映射全部 36 张现有帧，蓄势、伤害和收势阶段都必须绘制材质帧。
- 暴风式：360 tick 时间线按阶段使用全部 24 张现有帧，不再遗漏第 16、20～23 格。现有 24 张图不冒充先前计划要求的 96 张独立角色帧；补足 96 张独立姿势仍是明确的后续资产缺口。
- 技能角色帧始终跟随当前玩家位置；锁定中心只用于伤害、牵引和剑阵位置。
- 健康技能材质可用时，基础玩家 idle/攻击帧不与技能角色重复绘制，程序扇形、三角剑和椭圆终结效果不再作为主视觉。资源失败时才恢复基础玩家和现有程序效果。
- 两个技能获得独立 HUD 图标，并按槽位技能 ID 选择，不再共用通用蓝色圆球。

## 环境物件与死亡界面

水、雷、混沌的门、墙、洞口、灯具和障碍物从现有原创源图重新导出为独立透明单元。每个单元记录自身 alpha 边界、脚底锚点和推荐显示比例；正式房间在 800×450、1280×720、1920×1080 下均不得越界或遮挡 HUD。

死亡界面把 `MaterialPack` 作为只读依赖，中央面板使用 `ui_warning_modal` 九宫格，标题使用 `ui_label_plate`。全屏暗幕、动态文本和分隔线继续程序绘制。伤害数字与 `DEFEATED` 没有固定图片资源，继续动态绘制，但统一改用已加载的高清 HUD 字体。

## 输入修正

五个主动技能槽绑定 `KEY_KP_1`～`KEY_KP_5`，并同步 Win32 异步输入的 `VK_NUMPAD1`～`VK_NUMPAD5`。主键盘数字不作为已确认的小键盘需求的替代。输入修正不改变技能槽、冷却或保存格式。

## 资源与性能约束

- 峰值纹理显存保持不超过 256 MB。
- 不在每帧反复加载、卸载或查询磁盘；只有 residency 请求变化时才同步纹理。
- 图集、临时特效和请求集合继续使用固定容量数据结构，渲染热路径不增加堆分配。
- 30 怪物加暴风式场景目标为平均 60 FPS、1% low 不低于 45 FPS。
- 构建和测试默认串行或低并行运行；真实窗口与截图验收不与编译并发，避免不合理系统占用。

## 测试与验收

按 RED → GREEN 实施，至少新增以下失败测试后再修改生产代码：

- 火房间同时出现混沌怪物时，火背景、混沌怪物和公共门图集同时常驻，且预算不超限。
- residency 请求不变时不重复加载或卸载；单个图集失败只影响对应对象。
- 四个方向选择四种不同门材质；健康材质路径没有大面积红色覆盖和问号字符。
- 拔刀斩 0～35 帧全部可达；暴风式 0～23 帧全部可达；技能角色位置取玩家位置而不是锁定伤害中心。
- 健康技能素材下程序占位主视觉绘制计数为零；缺失素材时回退仍可用。
- 火怪附加姿势源矩形、锚点和阶段映射有效。
- 死亡面板实际调用九宫格材质；伤害文字使用 HUD 字体。
- 小键盘 1～5 的 raylib 与 Win32 两条输入路径均映射到正确槽位。

真实 raylib 验收覆盖 800×450、1280×720 和 1920×1080：

- 火房间中的异生态怪物不再是三角形或矩形。
- 四扇门细节可见、元素不同、关闭态无红色实心块、方向无问号。
- 拔刀斩蓄势/命中/收势与暴风式召唤/连斩/终结/收势均显示材质帧。
- 水、雷、混沌正式房间物件没有硬裁切、越界或 HUD 遮挡。
- 死亡界面使用统一暗钢古金 UI 材质。

最终运行相关单元测试、资产校验、Debug/Release 目标构建和一次真实窗口验收。不会为文档或每个小改动重复执行全量 109 项测试。

## 非目标

- 不修改游戏平衡、伤害数值、怪物 AI、碰撞或地下城规则。
- 不把攻击预警线、危险区精确边界、动态数字或全屏暗幕强行改成固定贴图。
- 不声称本批补齐尚不存在的火怪完整高帧率动作板或暴风式 96 张独立角色帧。
- 不删除旧资源；只有在后续独立审计证明无引用后才能讨论清理。
