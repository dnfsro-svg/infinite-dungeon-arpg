# Stage 11-C 完整 HUD 信息闭环设计

日期：2026-07-18
分支：`codex/stage11c-complete-hud`
基线：已验收 Stage 11-B `bd8c8be6dd02614c85a117d869520c57fa7aca1f`

## 1. 目标

Stage 11-C 将当前常驻左侧的开发信息面板替换为面向玩家的完整 HUD 信息闭环。HUD 必须让玩家在战斗、清房、选择出口、领取奖励和处理异常时，无需打开调试层即可读到当前决策所需的信息。

本阶段不修改战斗数值、固定时间步、随机流、地下城规则、物品生成、角色 V6 存档或 Stage 11-B 设置格式。HUD 是生产快照的只读表现层。

## 2. 范围

本阶段包含：

- 玩家生命、护盾、等级、经验和未分配星盘点；
- 玩家当前减速、腐蚀和短暂无敌等战斗状态；
- 房间波次、剩余目标、清房和出口状态；
- 深度、当前层房间序号、当前生态和四元素偏向；
- 洞口、四门、深渊奖励放弃、升级、奖励和存档异常等情境通知；
- 怪物已有生命、护盾、破韧的世界空间信息保留并统一视觉语言；
- F1 调试层承接预算、对象池、饱和、非法 owner、存档槽等开发诊断；
- 中文字体、三档分辨率布局、正式 raylib 截图和无分配门禁。

明确不包含：

- 地面物品过滤器或物品标签过滤规则；
- 主菜单、手柄、组合键、鼠标侧键；
- 分辨率列表、UI 缩放设置、画质设置；
- macOS 验证；
- 新战斗状态、目标锁定、首领血条、伤害数字重做；
- Stage 11-D 及以后内容。

## 3. 玩家可见信息层级

### 3.1 左下：玩家核心状态

左下常驻玩家面板，按从上到下的顺序显示：

1. 生命主条：红色，显示当前值/最大值；低于 25% 时以有界频率强调边框，不做全屏闪烁。
2. 护盾叠层：仅当最大护盾大于零时显示蓝色条和当前值/最大值。
3. 等级与经验：金色细条；100 级显示 `XP MAX`，不显示虚假的下一等级需求。
4. 未分配星盘点：大于零时显示中文可操作提示；战斗中只告知点数，不允许从 HUD 直接加点。
5. 状态短标签：减速、腐蚀、无敌等当前快照中真实存在且仍有效的状态，最多同时显示三个；额外状态在 F1 中诊断。

护甲、闪避、四元素减伤与上限等构筑明细不常驻显示，继续由背包属性页负责。

### 3.2 顶部中央：房间目标

顶部中央显示当前最重要的房间目标：

- 战斗阶段：`第 X/Y 波 · 剩余 N`；
- 波间等待：显示下一波状态，不泄露未生成内容；
- 清房后：显示出口已开放；
- 深渊房：以深渊配色显示危险等级、规则和待处理奖励；
- 提交/保存阶段：显示短暂的保存状态，不允许玩家误以为可以重复选择出口。

普通状态不显示 encounter budget、投射物数量或对象池数据。

### 3.3 右上：地下城导航

右上使用紧凑信息块显示：

- 深度；
- 当前层房间序号；
- 当前主生态；
- 火/水/电/混沌四个固定色块及各自偏向数字。

偏向只显示已提交快照中的数值，不预测下一房生态，不显示深渊或洞口的隐藏随机结果。

### 3.4 底部中央：情境通知

情境区最多同时显示一条主提示和一条次提示。主提示固定优先级：

1. 存档失败或恢复要求；
2. 深渊剩余奖励放弃二次确认；
3. 洞口或出口可交互提示；
4. 清房、奖励到账或升级；
5. 背包、星盘和当前可用操作提示。

低优先级提示不得覆盖高优先级提示。提示文本从已提交键位的 `ControlHints` 或稳定键标签生成，重绑定后不残留旧按键。

### 3.5 F1 调试层

以下信息仅在 F1 开启时显示：

- encounter 当前/总预算；
- 活跃怪物、投射物、危险区、Effect owner 数；
- 输入/事件溢出与对象池饱和计数；
- 投射物和危险区非法 owner 计数；
- Session tick、commit generation、房间 seed；
- 存档槽、存档错误和设置 revision；
- HUD 非法输入值、截断和通知溢出诊断。

## 4. 架构与组件

### 4.1 只读数据边界

新增 `HudViewModel` 作为无 raylib 绘制调用的固定容量数据模型。它只消费：

- `dungeon::DungeonSnapshot`；
- `combat::CombatSnapshot`（存在时）；
- `DungeonRenderStatus`；
- 已提交的 `ControlHints`；
- 平台层只读的通知表现状态。

构建 ViewModel 不得调用 `DungeonSession`、`DungeonRuntime::fixed_tick`、持久化 Store、随机数或输入采样；不得改变生产状态。

### 4.2 组件边界

平台表现层拆分为：

- `hud_view_model.hpp/.cpp`：校验快照、计算安全比例、选择提示、格式化固定缓冲区；
- `hud_layout.hpp/.cpp`：基于屏幕尺寸生成安全区和各面板矩形；
- `hud_notice_state.hpp/.cpp`：保存最多四条有界表现通知及寿命；
- `hud_renderer.hpp/.cpp`：字体、几何与颜色绘制；
- `debug_overlay_renderer.hpp/.cpp`：承接原常驻面板中的开发诊断。

`CombatRenderer` 负责组合世界、HUD、F1 调试层与既有覆盖层，不承担 HUD 业务规则。

### 4.3 固定容量与无分配要求

- ViewModel 文本使用 `std::array<char, N>`；
- 通知队列容量固定为四；
- 状态标签容量固定为三；
- 帧内不创建 `std::string`、`std::vector`、关联容器或动态字体字形表；
- 同一生产 revision 未变化时，不重复格式化静态导航与按键文字；
- 10 万次构建/布局/绘制准备压力测试的被测热路径必须为零堆分配。

Store I/O、启动时字体加载和正式截图写盘不属于热路径零分配范围。

## 5. 通知状态与时间

`HudNoticeState` 只属于表现层。通知来源必须是已存在的稳定快照变化或生产事件，例如 commit generation、房间 phase、reward revision、等级和保存状态变化。

- 通知寿命以呈现帧的真实秒数递减；
- 暂停期间通知计时冻结，避免玩家返回时错过信息；
- 房间切换清除不再相关的交互提示；
- 相同 revision 的通知不会重复入队；
- 队列满时按优先级丢弃最低项，并增加仅 F1 可见的溢出诊断；
- 通知状态不保存，不影响确定性 hash，也不参与角色或设置持久化。

## 6. 布局与视觉规范

### 6.1 分辨率与安全区

正式基准为 1280×720，并验证：

- 1024×576；
- 1280×720；
- 1920×1080。

布局以 16:9 逻辑安全区计算，边距按屏幕短边夹紧；条形保持逻辑宽高比，不因 1080p 直接拉伸一倍。面板不得覆盖中央玩家活动区、四门标签、洞口交互区或底部深渊确认框。

### 6.2 颜色与字体

- 生命：红色；
- 护盾：蓝色；
- 经验：金色；
- 火/水/电/混沌：红/蓝/黄/紫固定配色；
- 正常文字：高对比浅色；
- 错误：红色，但不与生命低警告使用完全相同的动态效果。

玩家可见文字以中文为主，保留 `HP`、`XP`、`F1` 等通用缩写。字体复用 Stage 11-B 已验证的 NotoSansSC 候选加载与 fallback；正式证据必须证明关键中文不是问号方块。

### 6.3 动效限制

只允许低成本透明度、边框和条形宽度变化。低生命、腐蚀和存档错误的强调频率必须有上限，不使用高成本模糊、实时阴影、粒子背景或全屏后处理。

## 7. 覆盖层与输入关系

HUD 不读取按键状态，也不接收鼠标命中。

- 暂停、设置、背包、星盘、死亡和恢复界面仍按既有优先级覆盖 HUD；
- HUD 可在暗化背景后保留，但情境通知不得绘制到覆盖层上方；
- F1 仍是全局安全键，只切换调试层；
- 截图键和设置重绑定语义不变；
- Stage 11-C 不新增任何玩法输入或输入延迟路径。

## 8. 异常与边界处理

- 缺少 `CombatSnapshot`：隐藏玩家战斗条，在 F1 显示一次受控诊断；不显示伪造的零生命。
- 当前值超出合法范围：ViewModel 夹紧绘制比例并记录诊断；不反向修改快照。
- 文本超长：固定缓冲区必须 NUL 终止并使用明确的省略/短标签；不得越界。
- 字体加载失败：使用现有 fallback，F1 显示字体状态；正式中文验证必须失败而不是接受问号。
- 保存错误：主提示保持到错误状态变化，不被升级或交互提示覆盖。
- 极端偏向、深度或房间序号：使用饱和格式化和固定最大宽度，布局保持在安全区。

## 9. 测试与正式证据

### 9.1 单元和边界测试

- ViewModel：正常、无战斗快照、低生命、护盾、满级、未分配点、三种状态、极端计数；
- 提示优先级：所有主/次提示组合与同 revision 去重；
- 布局：三档分辨率，面板边界、互不重叠和中央活动区保留；
- 字符串：最长值、NUL 终止、中文标签和重绑定键；
- F1：正常 HUD 不含预算/对象池/owner 诊断，调试层完整承接；
- 分配：10 万次 ViewModel/布局/未变化通知刷新零堆分配。

### 9.2 架构和源码守卫

- core/combat/dungeon/items/progression/passives/persistence/settings 继续不依赖 raylib；
- HUD 模块不得调用 Session、Store、随机数、输入采样或固定 tick；
- 正常 HUD 源码不得保留旧常驻调试句子；
- 绘制路径只消费当前帧已构建的 ViewModel；
- 守卫自测必须能拒绝在 HUD 中新增输入采样、Session tick、动态字符串和未受控诊断文本。

### 9.3 正式 raylib 场景

通过生产 host、生产快照和后 `EndDrawing()` 的唯一截图 helper，生成 fresh 1280×720 证据：

1. 正常战斗 HUD；
2. 低生命并带异常状态；
3. 清房、出口开放与情境提示；
4. 深渊奖励放弃确认；
5. 升级和未分配星盘点；
6. F1 调试层。

验证器检查尺寸、新鲜度、场景摘要、关键区域非空、面板矩形和关键中文字体状态。证据守卫拒绝私有快照 setter、直接 ViewModel 注入、Present 前截图和绕过生产 host 的场景。
