# Stage 7：64 节点被动技能星盘 MVP 设计

## 1. 目标与范围

在现有单角色、无限地下城的 Stage 6 代码上，交付一张**64 节点**、可实际改变战斗、可安全存档的永久被动技能星盘。

- 单角色共用一张星盘；节点 0 为免费且永久激活的起始节点。
- 每次升级获得的被动点用于激活其余节点；允许保留未分配点。
- 星盘仅可在房间清理、奖励已结算且尚未提交出口的 `awaiting_exit` 阶段操作。
- 使用全屏覆盖层。`P` 开关；鼠标点击节点。`Esc` 保留现有退出游戏语义，不被星盘截获。
- 星盘借鉴《流放之路 2》的构筑语言：旅行成本、连通图、小节点、显著节点、关键节点，以及强收益配明确代价；不复制其具体节点、名称或数值。

本阶段不实现装备、掉落、背包、职业起点、主动技能、暴击、异常状态、穿透、伤害转换、资源系统、重置货币、怪物随机词条或任何 Stage 8 内容。

## 2. 两条独立属性轴

元素不是角色职业属性。系统严格区分伤害/抗性类型与通用战斗属性。

### 2.1 伤害与抗性类型

新增稳定 `DamageType`：`physical`、`fire`、`water`、`lightning`、`chaos`。

- 任何伤害使用固定五分量 `DamagePacket`；每一分量是非负整数。
- 抗性只有 `fire`、`water`、`lightning`、`chaos` 四项；物理没有伪元素抗性。
- 玩家四项基础抗性均为 0%；最终每项使用有符号基点，先钳制到 `[-6000, 7500]`，即 -60% 至 75%。
- 当前八种怪物的接触、投射物和地面伤害各自带其目录生态对应的一种元素分量：火、水、电或混沌。
- J/K/L/空中 J 的基础攻击仍为物理近战。已分配的元素节点为每次近战命中加入独立的同类型附加伤害，不把基础物理伤害转换为元素。

### 2.2 通用角色属性

以下均为独立 `StatId`，不从节点所在元素路线推断含义：最大生命、最大护盾、近战伤害、承伤减免、移动速度、攻击速度、击退/击飞冲量、跳跃速度与空中操控。

护盾是玩家的额外生命层：每个新房间按最大值充满；同一房间内不自动回复。一次受击先计算各元素抗性和通用承伤减免，再由护盾吸收，余量再扣生命。

### 2.3 固定计算顺序

所有比例均复用 `modifiers::kFixedOne == 10000` 的定点表示和现有“flat → increased/reduced → more/less → clamp”求值顺序。

1. 每段攻击以攻击定义的 `damage` 作为物理基础值；每种元素以已分配节点的附加平坦值作为基础值。
2. 对每个分量分别结算其平坦、提高/降低和更多/更少；随后结算作用于全部近战分量的通用近战伤害。
3. 每个最终分量向下取整为非负 `int`，再写入 `DamagePacket`；事件和 HUD 显示最终总伤害。
4. 受击时，火/水/电/混沌分量分别按自身最终抗性结算；物理分量不使用元素抗性。
5. 合并剩余分量后应用通用承伤减免，减免最多 50%。护盾吸收最终伤害，剩余伤害扣除生命。

攻击速度只缩短攻击的启动和恢复 tick，活跃帧数量不变且所有阶段至少为 1 tick；移动、跳跃、空中操控和冲量分别只缩放原有对应基础量。节点不改变输入缓冲、命中判定顺序、RNG 或怪物 AI 时序。

## 3. 64 节点图与稳定数据

节点定义位于编译期扁平数组，稳定 ID 为 0 至 63；分配状态为一个 `uint64_t` 位图。节点 0 的位必须恒为 1，其他位各消耗 1 点。每个定义包含稳定 ID、类型、显示名、二维布局坐标、固定邻接表和不超过 3 条通用 `Modifier`。

| 类型 | 数量 | 作用 |
| --- | ---: | --- |
| Start | 1 | 免费起点、连通搜索根 |
| Connector | 8 | 四条路线各两个旅行节点，只制造路径成本 |
| Small | 39 | 小幅单项或双项数值修正 |
| Notable | 12 | 明确的局部构筑奖励 |
| Keystone | 4 | 强收益与不可忽略的代价 |

### 3.1 中央节点（ID 0–7）

起点 0 与节点 1–7 以及四条路线入口 8、22、36、50 相邻。节点 1–7 分别提供：

| ID | 稳定名 | 类型 | Modifier |
| ---: | --- | --- | --- |
| 0 | `origin` | Start | 无；永久激活 |
| 1 | `core_vitality` | Small | 最大生命 +20 |
| 2 | `core_guard` | Small | 最大护盾 +10；承伤减免 3% |
| 3 | `core_strength` | Small | 近战伤害提高 6% |
| 4 | `core_cadence` | Small | 攻击速度提高 5% |
| 5 | `core_force` | Small | 击退与击飞冲量提高 10% |
| 6 | `core_stride` | Small | 移动速度提高 6% |
| 7 | `core_aerial` | Small | 跳跃速度与空中操控提高 10% |

### 3.2 四条元素路线（每条 14 节点）

火、水、电、混沌路线的 ID 起点分别为 8、22、36、50。对任一路线，`B` 是路线起点：

| 相对 ID | 类型 | 邻接关系 | 固定效果 |
| ---: | --- | --- | --- |
| `B+0` | Connector | 0 ↔ `B+1` | 无 |
| `B+1` | Connector | `B+0` ↔ `B+2`、`B+5`、`B+8` | 无 |
| `B+2` | Small | `B+1` ↔ `B+3` | 对应元素附加伤害 +3 |
| `B+3` | Small | `B+2` ↔ `B+4` | 对应元素附加伤害 +3 |
| `B+4` | Small | `B+3` ↔ `B+10` | 对应元素伤害提高 8% |
| `B+5` | Small | `B+1` ↔ `B+6` | 对应元素抗性 +7% |
| `B+6` | Small | `B+5` ↔ `B+7` | 对应元素抗性 +7% |
| `B+7` | Small | `B+6` ↔ `B+11` | 对应元素伤害提高 8% |
| `B+8` | Small | `B+1` ↔ `B+9` | 近战伤害提高 4% |
| `B+9` | Small | `B+8` ↔ `B+12` | 承伤减免 2% |
| `B+10` | Notable | `B+4` ↔ `B+13` | 对应元素附加伤害 +8；对应元素伤害提高 15% |
| `B+11` | Notable | `B+7` | 对应元素抗性 +15%；最大护盾 +8 |
| `B+12` | Notable | `B+9` | 最大生命 +12；移动速度提高 3% |
| `B+13` | Keystone | `B+10` | 见下表 |

元素路线内出现的生命、护盾、移动或近战数值仍是独立属性；它们位于该路径仅意味着获取它们需要支付相应的旅行节点成本。

| ID | 稳定名 | 关键节点效果 |
| ---: | --- | --- |
| 21 | `cinder_vow` | 火焰伤害更多 30%；水抗性 -20% |
| 35 | `tide_bastion` | 水伤害更多 25%；最大护盾 +24；近战伤害降低 15% |
| 49 | `stormstep` | 电伤害更多 25%；移动与攻击速度各提高 12%；最大生命 -20% |
| 63 | `blood_pact` | 混沌伤害更多 30%；全部最终承伤提高 15% |

`B+13` 因此依次是 21、35、49、63。关键节点的“更多”“降低”和“最终承伤提高”均以定点独立修正记录；不通过字符串或路线颜色解释。

## 4. 分配、退款与持久化事务

### 4.1 分配合法性

请求分配时，系统必须同时满足：

1. 当前房间为 `awaiting_exit`，没有出口/下坠/星盘保存事务，也不处于 fault。
2. 目标 ID 在 1–63，尚未分配，且至少有一个直接相邻的已分配节点。
3. `unspent_passive_points` 大于 0。
4. 假设分配后的位图通过从 0 开始的固定容量 BFS；所有置位节点均被访问。

通过后，`unspent_passive_points` 减 1，构造下一份稳定检查点并进入“保存中”。在 `SaveStore` 返回 committed 前，不向玩家展示该点为已分配，也不允许第二次加点、退点或选出口。

### 4.2 免费退款

退款仅接受 ID 1–63 的已分配节点。先在副本位图中清除目标，再从节点 0 做固定容量 BFS：若任一剩余已分配节点无法连通，退款拒绝；否则未分配点加 1，并走与加点完全相同的双槽提交事务。这个规则允许退叶子或不割裂图的节点，禁止从中间拔掉旅行节点而保留远端节点。

### 4.3 存档格式和恢复

`DungeonRunState` 新增 `PassiveTreeState`，其中仅有 `allocated_bits`。点数不重复存储：解码验证 `popcount(allocated_bits & ~1) + unspent_passive_points == earned_passive_points`。

- 新检查点格式版本为 3，魔数为 `IARPGS04`，载荷为 88 字节，总大小为 120 字节；新增的 8 字节为 little-endian `allocated_bits`。
- 格式 1 与格式 2（旧魔数 `IARPGS03`）均可读取，并迁移为仅节点 0 激活的位图；格式 1 原有进度迁移为 Stage 5 已定义的 1 级、0 经验、0 点。
- 格式 3 必须拒绝：节点 0 未置位、未知高位、超点、断链、无效节点定义或无效 progression 关系。
- 加点/退点不依赖房间转场。`DungeonSession` 为星盘变更生成独立的 pending checkpoint mutation；`DungeonRuntime` 复用既有 A/B 槽 `SaveStore` 提交、验证状态和 generation 递增逻辑。提交失败保持旧稳定状态；不自动重试。
- 只要 mutation 存在，出口和下坠请求都拒绝；恢复后只能取得最后完整提交的旧状态或新状态。

## 5. 模块边界和数据流

新增无 raylib 依赖的 `passives` 静态库：

- `passive_tree_types.hpp`：64 位状态、节点类型、命令、拒绝原因和只读快照。
- `passive_tree_catalog.cpp/.hpp`：唯一的 64 节点扁平定义、稳定坐标和邻接关系。
- `passive_tree_rules.cpp/.hpp`：分配/退款合法性、固定容量 BFS、点数不变量、位图验证和已分配节点到 `Modifier` 列表的确定性投影。

`modifiers` 扩展通用 `StatId` 与定点求值能力；它不了解星盘图、地下城、存档或 raylib。`passives` 只依赖 `modifiers` 和 `progression`。

`combat` 接受一个纯数据的 `PlayerCombatBuild`，其中包含已求值的伤害、抗性、生命、护盾和移动参数；`combat` 不依赖 `passives`。构造每个新房的 `CombatWorld` 时，`dungeon` 从稳定的 `PassiveTreeState` 求值并提供该 build。这样在清房时变更星盘不会重建仍在展示的旧房间战斗世界，下一房才使用新 build。

`persistence` 仅编码 `DungeonRunState` 中的位图并调用 `passives::valid_state`；`platform/raylib` 只发送 P 键/鼠标命令、渲染快照并显示提交状态，不能自行修改节点或点数。

## 6. UI 与输入

全屏星盘覆盖层只在允许阶段显示。它绘制四条颜色不同的路线、节点类型轮廓、连线、已分配状态、可分配状态、当前未分配点、鼠标悬停详情、关键节点的收益/代价，以及保存中/被拒绝原因。

- `P`：仅允许阶段切换覆盖层；不允许时保留游戏输入且显示短暂拒绝原因。
- 鼠标左键：已分配节点尝试退款，未分配节点尝试分配；连接不可达、无点、会断链或保存中时不生成 mutation。
- 覆盖层显示时，移动、J/K/L、出口和下坠输入均不转发到 `DungeonSession`。
- 关闭覆盖层后恢复原 HUD 与门交互；HUD 始终从同一只读 `DungeonSnapshot` 读取等级、未分配点和星盘分配状态。

## 7. 测试与验收

1. 目录严格包含 64 个连续稳定 ID、对称四路线、无自环/重复边，所有节点从起点可达。
2. 分配只接受相邻已分配节点；无点、重复、未知 ID、战斗中、转场中和保存中请求均拒绝。
3. 退款只接受不切断任一剩余已分配节点的操作；点数守恒在 0、部分构筑和 63 个付费节点边界严格成立。
4. 同一位图无论分配顺序如何，Modifier 投影和 `PlayerCombatBuild` 均逐字段相同。
5. 五分量玩家攻击、四种生态怪物攻击、0%、75%、负抗性、护盾吸收、通用承伤减免和四个关键节点的收益/代价均有精确黄金测试。
6. 旧格式 1/2 迁移、格式 3 round-trip、畸形位图、CRC 破坏、加点/退款在 A/B 槽故障注入下的恢复均通过；不会重复扣点、丢点或越过未保存 mutation 选出口。
7. raylib 纯视图测试验证节点投影、悬停命中、可用/不可用颜色状态和 P 键门控；窗口 smoke 验证清房后能打开、分配、退款、关闭并进入下一房。
8. Debug 与 Release 全量 CTest、1000 房间确定性压力回放、热路径零分配检查和既有模块边界检查全部通过。
