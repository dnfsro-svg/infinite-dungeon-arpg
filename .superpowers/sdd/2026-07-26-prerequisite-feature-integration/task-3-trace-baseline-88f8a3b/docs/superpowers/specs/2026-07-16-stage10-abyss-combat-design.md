# Stage 10 正式深渊房间战斗设计

日期：2026-07-16
分支：`codex/stage10-abyss-combat`
基线：Stage 9 已合并的 `main`（`c756751`）

## 1. 目标

Stage 10 把 Stage 3 至 Stage 9 一直保留为展示标记的深渊房，升级为一次机会的正式房间级挑战：

- 深渊只影响单个房间，不影响整层。
- 深渊沿用普通房间、怪物、词缀、装备和存档系统，不创建第二套游戏循环。
- 玩家能在四向门上提前看到目标房是否为深渊，但看不到规则、危险等级或奖励详情。
- 深渊房以更高遭遇预算、怪物词缀下限和一条房间规则提高风险。
- 清房后自动结算确定性深渊宝箱；失败永久消耗该房唯一挑战资格。
- 所有资格变化由原子存档门禁保护，不能通过重启回滚。

## 2. 范围

### 2.1 本阶段包含

- 四向门目标房独立的固定 1% 深渊判定与门上标记。
- 深渊挑战 `available → started → cleared / failed` 生命周期。
- 9 条房间规则及深度危险权重。
- 普通遭遇预算 `+50%` 和怪物普通词缀补足下限。
- 一次机会、死亡/R/退出失败、启动与失败存档门禁。
- 自动结算的 1～3 件深渊装备奖励。
- 地面池不足时的部分生成、待生成、离房放弃二次确认。
- 存档格式升级、旧状态迁移、确定性重载和 raylib 表现。

### 2.2 本阶段不包含

- 深渊首领、层主或新怪物种类。
- 第 13 条怪物词缀、深渊专属怪物词缀、召唤或强化光环。
- 深渊专属装备、材料、货币、工艺或奖励邮箱。
- 返回旧房间、房间常驻图或保存战斗中怪物位置/生命。
- Stage 11 内容。

## 3. 方案比较与结论

曾比较三种实现：

1. **房间描述 + 独立深渊状态**：房间种子确定内容，存档保存生命周期和奖励进度。
2. **全部实时派生**：只存失败标记，其他内容都重建。
3. **通用房间变异器**：先建设更通用的规则框架，再把深渊作为首个使用者。

采用方案 1。它能最直接地满足一次机会、启动存档门禁、部分奖励生成和防复制，同时不把 Stage 10 扩大成通用内容框架。方案 2 无法可靠表达部分奖励和离房放弃；方案 3 的扩展性更强，但超出当前里程碑。

## 4. 稳定房间生成与门预告

### 4.1 出现范围

- 深渊只允许出现在四向门目标房。
- 初始房永远不是深渊。
- 普通下层洞的目标房永远不是深渊。
- 深渊房仍可带有当前房自己的 10% 下层洞；清房后可正常下层。

### 4.2 四向门独立判定

当前房的四扇门分别使用现有 `derive_door_room_seed(current.seed, next_index, direction)` 得到目标房种子，再用既有深渊命名域对该目标种子执行一次 `next_bounded(10000) < 100`。

- 四个方向彼此独立；同一当前房可能有 0～4 扇深渊门。
- 概率始终为 `100 / 10000 = 1%`，不受深度、历史、生态或玩家状态影响，无保底。
- 不新增会消费生态、洞口、普通遭遇、普通怪物词缀或普通掉落随机状态的顺序流。
- 门上只绘制深渊符号，不显示规则类别、具体规则、危险等级或宝箱件数。
- 玩家直接穿门进入，操作与普通门一致，不增加二次进入确认或 E 交互。

目标房提交后，其 `RoomDescriptor::is_abyss` 必须与门预告完全一致。初始房和洞口目标的构造路径必须显式写入 `is_abyss=false`，不能依赖概率偶然未命中。

### 4.3 旧状态迁移

旧存档若把初始房或下层洞目标房标记为深渊，加载时按普通房迁移：

- 清除非法深渊资格和深渊运行状态。
- 保留房间种子、索引、深度、生态、洞口、方向偏向、物品和进度。
- 迁移结果必须通过下一次原子发布保存；发布失败进入故障态。

## 5. 深渊生命周期与一次机会

### 5.1 稳定状态

深渊生命周期固定为：

```cpp
enum class AbyssChallengeState : std::uint8_t {
    none,
    available,
    started,
    cleared,
    failed,
};
```

- `none`：普通房或被迁移为普通房。
- `available`：目标房是合法深渊，尚未开始。
- `started`：启动门禁已持久化，挑战正在进行或上次异常退出。
- `cleared`：挑战通关，规则已解除，奖励结算状态继续保留。
- `failed`：唯一机会已消耗，该房按普通房重建且没有深渊宝箱资格。

规则 ID、危险等级和奖励内容由稳定房间数据确定性派生；规则版本固定为 `abyss_rules_version = 1`。存档保存已确认的规则 ID 与规则版本以便校验重建结果，任何不一致均为非法状态。

在把 `started` 写盘前，dungeon 必须先纯计算并完整验证规则、强化遭遇和宝箱描述，但不能生成怪物、应用规则或发放奖励。这样可以在消耗资格前拒绝确定性的非法配置；资格一旦成功写成 `started`，后续异常仍按一次机会失败处理。

### 5.2 进入与启动门禁

玩家穿过深渊门并完成目标房切换后，不立即生成怪物：

1. 房间进入 `available`。
2. 创建原子存档事务，把状态写为 `started`。
3. 存档发布成功后，封锁房门、应用规则、加载强化遭遇并开始战斗。
4. 发布失败则进入 `RoomPhase::faulted`；不生成怪物、不应用规则、不开放挑战。

这保证开始挑战后退出或崩溃不能恢复未开始资格。

### 5.3 失败条件

以下情况永久消耗唯一机会：

- 玩家死亡。
- 玩家按 R 重置当前房。
- 游戏退出、进程崩溃或系统中断后，存档仍为 `started`。

死亡和 R 的处理顺序：

1. 创建原子事务，把深渊状态写为 `failed`。
2. 发布成功后解除深渊规则。
3. 沿用普通死亡/R 流程：恢复玩家、按同一房间种子重建普通遭遇。
4. 保留房间生态、门、洞、房间种子和进度；移除深渊预算、强制词缀和宝箱资格。
5. 发布失败进入故障态，不重建、不继续深渊战斗。

加载时看到 `started` 表示上次异常退出。加载流程必须先原子迁移到 `failed`，发布成功后才构造普通房；失败进入故障态。

### 5.4 清房

最后一波清理后：

1. 深渊状态原子提交为 `cleared`。
2. 解除房间规则并恢复玩家派生属性。
3. 自动开始宝箱奖励结算。
4. 出口与同房下层洞按普通清房规则开放。

规则解除后玩家最大生命恢复，当前生命按挑战结束前的生命百分比映射到正常上限；不得凭空治疗或额外重伤。比例映射统一使用有检查的 64 位中间值和最近整数取整：`mapped = floor((current * new_max + old_max / 2) / old_max)`，存活角色最低为 1、最高为新上限。屏障上限恢复，但当前屏障仅向下钳制，不免费补满。

## 6. 深度、危险等级与规则抽取

### 6.1 危险等级权重

每个合法深渊目标房用独立命名域先抽取危险等级：

| 深度 | 低危 | 中危 | 高危 |
| --- | ---: | ---: | ---: |
| 1～9 | 70 | 25 | 5 |
| 10～19 | 45 | 40 | 15 |
| 20～39 | 25 | 45 | 30 |
| 40+ | 10 | 35 | 55 |

选中等级后，在该等级对应的环境、怪物、玩家三条规则中等概率抽取一条。危险等级流和规则选择流相互独立；同一房间种子、深度和规则版本必须产生相同结果。

### 6.2 规则目录

规则目录是固定、无字符串运行时数据；展示名称在平台层或只读目录中查询。

| 危险 | 类别 | 规则 | 精确效果 |
| --- | --- | --- | --- |
| 低 | 环境 | 雷暴 | 每 180 tick 锁定玩家当时位置；预警 45 tick、半径 0.8；命中造成实际最大生命 15% 的闪电伤害。 |
| 中 | 环境 | 追猎烈焰 | 每 240 tick 锁定玩家当时位置；预警 45 tick、半径 1.0；燃烧持续 180 tick，每 60 tick 造成实际最大生命 10% 的火焰伤害。 |
| 高 | 环境 | 混沌扩散 | 从房间中心开始，半径固定为 `1.0 / 2.3 / 3.6 / 4.9 / 6.2` 五档，每 180 tick 扩大一级；圆形区域裁剪到房间边界后覆盖约 45% 可战斗区域；区域内每 60 tick 造成实际最大生命 8% 的混沌伤害。 |
| 低 | 怪物 | 迅捷追猎 | 所有怪物移动速度 `+15%`，技能冷却时间乘 `85%`。 |
| 中 | 怪物 | 深渊壁垒 | 所有怪物现有护甲 rating 乘 `130%`，并获得最大生命 30% 的额外护盾；无基础护甲的怪物仍由护盾获得强化。 |
| 高 | 怪物 | 深渊狂怒 | 所有怪物最终伤害乘 `145%`；标准攻击速度乘 `145%`，因此 telegraph、recovery 和 cooldown 使用 `ceil(base_ticks * 10000 / 14500)`，active 有效帧不变。 |
| 低 | 玩家 | 沉重脚步 | 玩家地面移动速度乘 `85%`；不改变跳跃、空中状态或攻击。 |
| 中 | 玩家 | 枯竭恢复 | 进入深渊时生命与屏障只恢复到各自上限 70%；挑战期间所有未来恢复量乘 `70%`。 |
| 高 | 玩家 | 生命献祭 | 玩家最大生命乘 `55%`；当前生命保持进入规则前的百分比。 |

生命献祭生效时也使用上述最近整数比例映射；规则结束时基于结束瞬间的 `current_hp / reduced_max_hp` 再映射回正常上限。所有 basis points 运算使用有检查的 64 位中间值和明确取整。时序至少为 1 tick。深渊怪物倍率与现有 Stage 9 怪物词缀倍率乘算，不覆盖已有 profile。

### 6.3 环境伤害

- 雷暴、燃烧和混沌区属于 `ground_or_environment`，不投玩家闪避率。
- 伤害仍经过对应的闪电、火焰或混沌减伤。
- 百分比以规则生效后的实际最大生命为基准。
- 原始百分比伤害使用 `ceil(actual_max_hp * percent_bp / 10000)`，最大生命大于 0 时伤害至少为 1；之后再进入现有元素减伤结算。
- 雷暴预警在挑战 tick `180, 360, 540, ...` 创建，45 tick 后命中；追猎烈焰预警在 `240, 480, 720, ...` 创建，45 tick 后生成燃烧区。混沌扩散从挑战开始即处于第一档，之后在 `180, 360, 540, 720` tick 扩大，最终保持第五档。
- 预警与伤害区域使用固定容量 hazard 池；池满时安全降级、增加诊断计数，不覆盖旧对象、不伪造成功事件。
- 环境规则不得递归触发怪物的连锁闪电、腐蚀或其他直接命中词缀。

## 7. 遭遇强化与词缀补足

### 7.1 遭遇预算

先按普通房规则计算基础预算，再应用：

```text
abyss_budget = ceil(normal_budget * 3 / 2)
```

结果必须经过现有容量验证；无法构造合法计划时显式失败，不静默退回普通预算。

### 7.2 怪物词缀下限

先完整执行 Stage 9 普通词缀生成，再使用独立深渊补足域只补充缺少的词缀：

| 深度 | 每只怪物最少词缀数 |
| --- | ---: |
| 1～19 | 1 |
| 20～39 | 2 |
| 40+ | 3 |

- 已有普通词缀 ID 与等级完全保留，不重骰。
- 新增词缀仍须满足 monster required tags、无重复和冲突规则。
- 补足的每个选择和每个 tier 按输出位置派生独立子流。
- 候选不足必须显式失败，不允许少于下限继续开战。
- 不增加高危词缀数量上限。
- 怪物普通词缀危险分、经验和普通掉落公式保持 Stage 9 原样。

## 8. 深渊宝箱奖励

### 8.1 结算边界

- 深渊房清理后自动结算，不需要按 E 开箱。
- 怪物经验与普通地面掉落只由怪物自身词缀决定；房间规则不加成它们。
- 宝箱在房间中央按稳定奖励序号依次生成装备。
- 装备沿用普通地面装备的靠近自动拾取与原子领取存档流程。

### 8.2 件数与物品等级

| 危险 | 件数 | 宝箱物品等级加成 |
| --- | ---: | ---: |
| 低 | 1 | +1 |
| 中 | 2 | +3 |
| 高 | 3 | +5 |

基础物品等级取当前房间深度，最终封顶 100。每件装备部位独立随机，允许重复部位。

### 8.3 稀有度权重

先调用现有 `rarity_weights(final_item_level)`，再把白装权重向蓝/黄转移：

| 危险 | 白装变化 | 蓝装变化 | 黄装变化 |
| --- | ---: | ---: | ---: |
| 低 | -10 | +5 | +5 |
| 中 | -20 | +10 | +10 |
| 高 | -30 | +10 | +20 |

白装权重最低为 0。如果基础白装不足以提供全部转移量，先把白装降到 0，再按原定蓝/黄增量比例重新分配实际可转移量；使用整数最大余数法保证总和恰好为 100。不得从蓝装或黄装反向扣除来满足表面增量。

示例：100 级基础为 `40/40/20`，高危宝箱为 `10/50/40`。

### 8.4 确定性内容

每件奖励的所有随机内容只由以下稳定输入派生：

- 房间种子。
- 深渊奖励命名域。
- 奖励序号 `0..2`。
- 规则版本。

部位、稀有度、物品 ID 和词缀内容使用彼此独立的命名子域。清房时间、玩家构筑、生成重试次数和地面池可用位置不得改变奖励内容。

## 9. 部分生成、拾取与离房放弃

### 9.1 奖励进度

存档保存：

- 规则 ID 和危险等级。
- 宝箱总件数。
- 每个奖励序号是否已成功生成。
- 每个奖励序号是否已拾取/领取。
- 剩余待生成数量。
- 未生成奖励是否已永久放弃。

由于当前地下城不能返回旧房间，离房事务还保存一个固定 `LastAbyssResolution` 摘要：已解决房间种子、规则 ID、总件数、已生成数、已领取数和已放弃数。该摘要只用于重载、防复制审计和诊断，在下一次深渊结算时覆盖，不恢复旧房地面对象。

奖励内容本身可由稳定输入重建，但加载后必须校验生成/领取位图合法且互不矛盾。

### 9.2 地面池与背包容量

- 地面掉落池有空位时，按奖励序号从小到大生成。
- 池满时保留待生成状态；每 tick 最多按固定上限继续尝试，不能产生堆分配或无界循环。
- 已生成装备若因背包满无法自动拾取，继续留在地面，不退回待生成。
- 已拾取奖励通过现有物品事务原子保存；发布失败保持事务故障语义，不把领取位提前写入内存稳定状态。

### 9.3 离房二次确认

有待生成奖励或已生成未拾取装备时，出口仍显示开放，但离开需要二次触门：

1. 第一次触门取消离开，记录本次方向和当前奖励修订号，并提示：待生成 X 件、地面未拾取 Y 件，再次触碰同一扇门将永久失去它们。
2. 玩家离开门范围、触碰另一方向、奖励状态变化（新奖励生成或拾取）时，确认失效。
3. 在确认仍有效时再次触碰同一扇门，原子把所有未生成奖励标记为 `abandoned`，然后按普通门事务离开。
4. 原子提交失败则留在当前房间并进入故障态；不得先离开再写盘。

首次触门的临时确认只存在于运行时，不写存档。最终 `abandoned` 结果和 `LastAbyssResolution` 写入离房事务，并参与重载验证。已生成但未拾取的普通/深渊地面装备在离房后按现有规则丢失，不跟随到后续房间。

## 10. 模块边界

### 10.1 `abyss` 纯规则模块

新增 `src/abyss`，只提供固定数据和纯计算：

- 合法入口类型与门目标深渊判定。
- 深度危险权重和 9 条规则目录。
- 预算倍率与最少词缀数。
- 深渊补足选择所需的稳定随机上下文。
- 宝箱件数、等级、稀有度权重和奖励种子。

它依赖 `core` 的确定性 RNG、只读的 combat 词缀类型和 items 值类型；不依赖 `dungeon`、`persistence` 或 raylib。若现有依赖方向不允许直接依赖 combat/items，则把共享的稳定 ID/值结构下沉到无运行时依赖的类型头，不能形成循环依赖。

### 10.2 `dungeon`

负责：

- 四向门目标描述与预告快照。
- 深渊生命周期和原子存档请求。
- 强化遭遇计划组装。
- 深渊奖励生成状态、领取事务和离房二次确认。
- 加载迁移与故障态。

`dungeon` 不在渲染路径重新投掷规则或奖励。

### 10.3 `combat`

`combat` 只接收已求值的 `AbyssCombatConfig` 值对象：

- 规则 ID 和危险等级。
- 环境危害参数。
- 怪物倍率。
- 玩家限制倍率。

`combat` 不读取存档、不判断 1% 概率、不生成宝箱。运行时使用固定容量状态，combat tick 内零堆分配。

### 10.4 `persistence`

升级到下一检查点版本，编码深渊生命周期和奖励进度。`persistence` 仍只依赖稳定 checkpoint 值类型，不依赖 combat/dungeon 运行时。解码器必须：

- 接受旧版本并执行确定迁移。
- 拒绝非法枚举、越界规则 ID、矛盾位图和不可表示计数。
- 保持双槽、CRC、发布收据和故障矩阵语义。

### 10.5 raylib 平台层

平台层只读取快照，显示：

- 每扇门的深渊符号。
- 入房后的规则名称、危险等级与精确效果。
- 环境预警与危险区域。
- 宝箱结算、待生成件数、地面未拾取件数和离房放弃提示。
- 保存失败/挑战失败/挑战通关状态。

平台层不得判断规则效果、掉落内容或资格状态。

## 11. 存档原子性与故障矩阵

必须为以下边界逐一覆盖 `success / failure-before-publish / failure-after-uncertain-publish`：

- 进入深渊，把 `available` 提交为 `started`。
- 死亡或 R，把 `started` 提交为 `failed`。
- 加载异常退出状态，把 `started` 迁移为 `failed`。
- 清房，把 `started` 提交为 `cleared` 并创建奖励进度。
- 拾取深渊奖励，提交领取位。
- 二次确认离房，提交 `abandoned` 并切换房间。

确定失败可以回滚到事务前状态；发布结果不确定必须进入故障态并由 SaveStore 恢复逻辑判定最终稳定槽。任何资格变化都不得先在运行时生效、后尝试保存。

## 12. 确定性、容量和性能

- 所有新增随机使用独立的 64 位命名域和按输出索引派生的子流。
- 新增逻辑不得改变既有生态、普通洞口、房间种子、基础怪物选择、普通词缀或普通掉落 golden trace。
- 深渊计划、规则、补足词缀和宝箱内容必须在重载、部分生成和保存重建后逐字段相同。
- combat、hazard、奖励状态和事件使用固定容量。
- 96 怪、384 弹体、96 hazard、三高危词缀和高危深渊规则并存 600 tick 时分配增量为 0。
- 池满必须显式计数并安全降级；不能覆盖旧对象、伪造事件、重复奖励或丢失待生成进度。

## 13. 测试与验收

### 13.1 纯规则测试

- 四向门各自 1% 边界、方向独立和预告/进入一致。
- 初始房与下层洞目标强制排除；旧非法状态迁移。
- 深度权重边界 `1/9/10/19/20/39/40`。
- 9 条规则精确数值、类别、危险等级和显示目录。
- 预算向上取整和词缀补足下限；已有普通词缀不漂移。
- 宝箱件数、等级、稀有度权重和奖励序号独立随机域。

### 13.2 战斗测试

- 三种环境规则的预警、间隔、范围、百分比伤害、元素减伤和不可闪避。
- 三种怪物规则与 Stage 9 词缀乘算、active 帧不变。
- 三种玩家规则的生命比例、屏障、移动和恢复语义。
- 清房解除规则后的生命比例映射与屏障不免费补满。
- 死亡、R 和 `started` 重载只消耗一次资格。

### 13.3 dungeon / persistence 测试

- 启动、失败、异常退出、通关、拾取和放弃的完整原子故障矩阵。
- 深渊与同房下层洞共存。
- 1～3 件奖励、地面池部分生成、背包满、重载、领取和防复制。
- 离房二次确认的同门、换门、离范围和奖励修订失效规则。
- 旧检查点迁移、CRC、双槽回退和非法 payload 拒绝。

### 13.4 长程与窗口验收

- 两个独立 session 使用同一根种子运行至少 1,000 房，逐字段比较门预告、规则、强化计划、奖励和资格状态；每 37 房编码/解码后继续。
- 压力组合 600 tick 零分配。
- Debug 与 Release 全量 CTest 通过。
- 正式 raylib host 使用临时存档和固定种子，提供非白已提交帧证据：深渊门标记、规则 HUD、三种环境预警、宝箱掉落、待生成提示和离房二次确认。
- 人工验证死亡、R、退出后只剩普通房，且下层洞共存路径可用。

## 14. 完成边界

完成所有任务、双配置测试、正式窗口证据和完整分支审查后，停止在 `codex/stage10-abyss-combat` 工作树，等待用户验收与集成选择。不得开始深渊首领、专属装备/材料、召唤、光环或 Stage 11。
